## 门禁配置

阈值写死在 `backend/pyproject.toml`，低于 60% 直接判失败，不依赖人工检查：

```toml
[tool.pytest.ini_options]
addopts = "-q --strict-markers"
testpaths = ["tests"]

[tool.coverage.run]
source = ["app"]
omit = ["app/infrastructure/*"]   # 外部网关（LLM、HTTP 抓取）不计入，避免用桩测试凑覆盖率

[tool.coverage.report]
fail_under = 60
show_missing = true
skip_covered = true
```

覆盖率较高的模块（≥ 85%）：发现算法、聚类算法、人才评估、需求 DSL、简历抽取、LLM 命中复核。
覆盖率较低的模块集中在离线管线入口（`organization/ingest.py`、`job/parsing_service.py`），
它们由 `tools/` 下的命令行工具驱动，走的是数据装载路径而非单元测试路径。

## 复现命令

**后端生产镜像不含测试代码**：`Dockerfile` 只拷贝 `app`、`tools`、`migrations`、`data`，
且 `pytest` 属 `dependency-groups.dev`，不在运行镜像内。因此需挂载源码另起容器执行。

```bash
docker run -d --name jcg-test --network job-capability-graph-latest_default \
  -v "$PWD/backend:/srv/backend" \
  -v "$PWD/data:/srv/data:ro" \
  -v "$PWD/frontend:/srv/frontend:ro" \
  -v "$PWD/docs:/srv/docs:ro" \
  -w /srv/backend \
  -e APP_DATABASE_URL="mysql+pymysql://app:app_password_change_me@mysql:3306/job_capability_graph?charset=utf8mb4" \
  job-capability-graph-backend:latest sleep infinity
```

```bash
docker exec jcg-test pip install -q "pytest>=8.4,<9" "pytest-cov>=6.2,<7" "httpx>=0.28,<1"
```

```bash
docker exec jcg-test python -m pytest --cov=app --cov-report=term --cov-report=html:/tmp/htmlcov
```

```bash
docker cp jcg-test:/tmp/htmlcov ./coverage && docker rm -f jcg-test
```

### 四个挂载缺一不可

三个只读挂载不是可有可无——缺哪个都会让对应测试因**找不到文件**而失败，与代码无关：

| 挂载 | 不挂时失败的测试 | 缺失文件 |
| --- | --- | --- |
| `data` | `test_job_real_import.py`、`test_taxonomy_real_import.py` | `/srv/data/source/20260810/core/*.xlsx` |
| `frontend` | `test_industry_job_graph.py`（6 项） | `/srv/frontend/public/enterprise-industry-graph.json` |
| `docs` | `test_holdout_experiment.py`（2 项） | `/srv/docs/reports/holdout实验报告模板.md` |

首次实测只挂 `backend` 时为 4 failed + 6 errors、覆盖率 72.48%；逐个补齐挂载后全部转绿，
覆盖率升至 78.79%。**这 10 项失败全部是环境缺文件，没有一项是代码缺陷。**
