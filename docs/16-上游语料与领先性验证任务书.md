# 上游语料与领先性验证任务书

## 为什么要做这件事

当前的「新岗位发现」存在一处**循环论证**：

```
3,718 份 JD ──聚类──→ 509 个岗位 / 676 个版本   ← 既有岗位库
     │
     └──挖频繁技术组合──→ 候选
                            │
                            └── 拿去和上面那个库比覆盖率
```

候选与岗位来自同一批 JD、同一套技术词表，候选必然落在岗位的技术集里。实测印证：
把可比岗位的画像门槛从 ≥2 技术词提到 ≥8（可比岗位从 532 砍到 66，去掉 88%），
**「未被既有岗位覆盖」始终是 0 个**。这不是阈值问题，是基线问题——拿语料跟它自己比。

因此现有产出只能回答「这个技术组合在我们自己聚出来的岗位库里有没有对应」，
不能回答「这是不是一个新岗位」。

### 「新」的三种含义，只有第一种是本任务的目标

| 含义 | 现状 | 归属 |
| --- | --- | --- |
| ① **市场上还没人在招** | 做不到 | **本任务书的目标** |
| ② 市场在招，但还没有公认的岗位定义 | 需外部职业标准作基线 | 岗位库的更新迭代 |
| ③ 我们自己的岗位库里没收录 | 已能做（`library_gap`） | 岗位库的更新迭代 |

②③ 是**数据库中岗位的更新迭代**，是真实可交付的产出，但不应称为「新岗位发现」。
本任务书只针对 ①。

### 唯一结构上成立的思路

岗位 = 雇主把一组能力打包成一个招聘需求。要在岗位出现**前**发现它，必须预测
**打包**，而不是预测能力。能力已可观测（里程碑），打包只能从「雇主在招人之前
干了什么」里看——研发、论文、专利、产品发布、融资，这些都发生在招聘之前。

判据：

> 两个技术在**上游语料**里反复一起出现，却在**任何一份 JD** 里都没被写进同一个岗位
> → 这个组合还没走到招聘环节

证据是真实的，不是外推。这是唯一既指向「尚未出现的岗位」、又不靠编造的做法。

## 已测出的两个前提缺口

动手前先测了两件事，结论决定了任务顺序。

### 缺口 A：现有上游语料太稀，撑不起共现分析

```
474 条里程碑，每条挂几个技术点：
   1 个技术: 317 条   ← 67%，对共现分析完全无用
   2 个技术: 118 条
   3 个技术:  39 条

L2 口径的技术对：里程碑 9 对  ·  JD 438 对   ← 差两个数量级
```

其中确有 3 对是「里程碑反复同现、JD 从未同现」（灵巧操作与抓取 + 力觉与触觉传感、
具身基础模型与VLA + 任务规划与推理、数据集与数据采集 + 数据标注与治理）——
**机制成立的存在性证据**，但 3 对撑不起一个模块，且更可能是整理时的分类习惯。

### 缺口 B：技术词表对英文语料只覆盖 17%

上游语料的自然来源是 arXiv / 专利，都是英文。而现有词表是中文导向的：

```
可匹配别名 2,039 条：纯中文 1,197 (59%) · 中英混合 694 (34%) · 纯英文 147 (7%)
242 个 L3 技术点中，有纯英文别名的只有 40 个 = 17%
```

**arXiv 不能直接接。** 管线跑通也只能识别六分之一的技术点，且识别不到的技术会
**看起来永远不共现**——共现分析会被这个缺口系统性扭曲，得出的结论方向都可能是反的。

## 任务 U-1　补英文别名（① 的前置，可独立分发）

顺序不能反：先补别名，再抓语料。

这是一次性、可复核的工作，与 v1.2 词表治理走同一套流程
（`build_taxonomy_workbook.py` + 变更集 JSON + 三项校验），不是新机制。

### 步骤

1. **圈定范围**——242 个 L3 中先补具身智能核心域（T1/T2/T3/T4）。
   现状 40 个有英文别名，目标覆盖到 200 个以上。
2. **生成候选别名**——LLM 按技术点批量产出英文别名，人工审核。
   与补 T5 里程碑同一套做法：LLM 出、人审、变更集落库、留 `review_notes`。
3. **歧义规则**——英文技术词歧义比中文更严重（`transformer` 是模型还是变压器，
   `attention` 是机制还是普通词义）。复用现有的 `technology_context_rules` 机制，
   为每个高歧义英文别名配上下文标记词。
4. **抽样验证**——取 100 篇 arXiv 摘要人工标注，测英文抽取的精确率与召回率。

### 验收标准

- 有英文别名的 L3 覆盖率 ≥ 80%（当前 17%）
- **英文抽取有自己的 P/R 数字**。中文侧测过受限口径 F1 0.505，英文侧必须有对应
  数字——没有它，下游一切结论都不知道能不能信。
- 同一表面形式不得跨技术点重复（沿用 v1.2 治理的既有校验）
- 歧义别名必须配上下文规则，不得裸放行

### 明确不做

不追求词表的英文「完整」，只求**覆盖到共现分析不被系统性扭曲**的程度。
覆盖率本身要随结论一并声明。

---

## 任务 U-2　抓取上游语料

U-1 验收通过后才开始。

- **来源**：arXiv API（`cs.RO` / `cs.AI` / `cs.LG` / `cs.CV`），公开、带发表日期、无需授权
- **规模目标**：JD 侧 1,707 份文档产出 438 个技术对；上游要达到可比密度，
  需要**千级以上文档、每篇平均挂 3 个以上技术点**
- **抽取**：直接复用 `build_alias_matcher()` 与证据跨度机制，只换输入源
- **落库**：新建上游文档表，**不要混进 `MilestoneEvent`**——里程碑是人工整理的
  精选事件，上游文档是批量抓取的原始语料，两者的证据强度与用途都不同，混在一起
  会让成熟度模型悄悄改变含义

### 验收标准

- 文档数 ≥ 1,000，平均技术点挂载数 ≥ 3
- 每篇文档带**发表日期**（不是抓取日期）
- 抽取结果可回溯到原文跨度

## 任务 U-3　领先性回测（决定这条路成不成立）

**这一步必须在做产品之前完成。** 上一轮我们先做了前瞻排序，回头才发现传导时滞
根本标定不了；这次先验证再建设。

### 关键设计：只切上游的时间，JD 当快照

采集时间 ≠ 发布时间 ≠ 岗位出现时间，三者层层脱节，**JD 侧的时间轴不能当真值**。
但回测不需要它：

```
for T in [2020, 2021, 2022, 2023, 2024, 2025]:
    P(T)   = 上游语料中【T 之前】共现 ≥ k 次的技术对
    P(now) = 今天 JD 快照里共现的技术对（不问采集时间）

    命中率 = |P(T) ∩ P(now)| / |P(T)|
    基准率 = |P(now)| / 所有可能的技术对
    提升度 = 命中率 / 基准率
```

唯一的时间轴在上游，而论文发表日、专利申请日、产品发布日都是**文档自带的属性**，
不是采集产物，这条轴是干净的。T 往前推得越远，测的领先期就越长——命中率与领先期
两个量同时得到，一个 JD 时间戳都不需要。

### 预注册判据（动手前定死，不等结果出来再改）

| 结果 | 结论 |
| --- | --- |
| 提升度 ≤ 1.5 | **证伪，停止**。上游共现不预测招聘需求 |
| 提升度 > 2 且随 T 前移单调下降 | 有领先信号，下降曲线的形状即领先期 |
| 提升度 > 2 但不随 T 变化 | 可能只是「热门技术恒热门」，需看对照臂 |

### 必须带的对照臂

**按单技术频次排序的基线**：不看共现，只按两个技术各自在上游出现的频次高低挑对。
若本方法的提升度与该基线相当，说明信号可被「热门技术更容易凑到一起」解释，
不构成共现的证据。

上一轮传导时滞标定就栽在没有对照上——最优切点的判别力与「里程碑条数」完全相同
（均 91.7%），说明那点可分性整理密度就能解释。这次一开始就带对照臂。

## 任务 U-4　组合成岗位并给出前瞻

**只有 U-3 通过才启动。** 把「上游已打包、招聘未打包」的技术对扩展成能力组合，
给出预期出现顺序。此处不展开设计——U-3 的结论会决定它该长什么样。

---

## 与当前模块的关系

本任务书**不影响**现有模块的继续交付。现有产出（含义 ②③：岗位库的更新迭代）
是真实可用的，需要做的只是把名实对齐：

- 界面与文档中的「新岗位发现」措辞需改为反映它实际在做的事
- `potential_new_role` / `library_gap` 的语义需说明其分母是**自产的岗位库**

这部分改动与 U-1 可并行。

## 执行结果（2026-08-26）

四个阶段全部执行完毕，结论见《上游共现领先性回测报告》。

| 任务 | 状态 | 结果 |
| --- | :---: | --- |
| U-1 补英文别名 | ✅ | 覆盖率 17% → 91%（词表 v1.3），补齐全称后 → v1.4 |
| U-2 抓取上游语料 | ✅ | 13,282 篇 arXiv，2019–2026 逐年 1,500–1,700 篇 |
| U-3 领先性回测 | ✅ | **部分支持**：携带频次外信息成立，领先期不成立 |
| U-4 组合成岗位并给出前瞻 | ⚠️ 降级 | **前瞻部分不启动** |

### U-3 的结论

| 检验的命题 | 结论 | 依据 |
| --- | :---: | --- |
| 上游共现携带 JD 频次之外的信息 | ✅ 支持 | 剂量-反应：门槛 ≥2→≥8 时提升度 2.24→2.94，对照臂持平 2.13–2.25 |
| 上游共现领先招聘需求若干年 | ❌ 不支持 | 七个切点提升度基本持平，不随 T 前移下降 |

### 对 U-4 的处置

原定「U-3 通过才启动 U-4」。按结果，**U-4 的「前瞻」部分不启动**——没有领先期
证据，给出时间预测就是编造，与本项目一贯的口径冲突。

可启动的是降级版本：把「上游反复共现、JD 尚未共现」的技术对作为**值得关注的
能力组合**提示出来，措辞限定在「值得关注」，不含任何时间断言。

### 两处翻转过结论的实现缺陷

均已修复并记入报告：对照臂按枚举顺序取对（导致提升度乱跳）、判定逻辑未区分
「随 T 下降」与「不随 T 变化」（导致平坦曲线被报成有领先期）。

### 别名生成的一处默认值错误

首轮只补「完全没有英文别名」的技术点，漏掉了强化学习、运动规划、模仿学习——
它们已有的 `PPO`/`MoveIt`/`Diffusion Policy` 全是缩写与产品名，恰恰缺正文里最常
出现的全称。默认已改为全部处理。**修正前后默认门槛下的相对优势从 1.17× 降到
1.05×**——数据变好使假象消失，这也是结论必须建立在剂量-反应而非单点比较上的原因。
