## 数据真实性边界

3,718 条 JD 中只有 1,691 条带来源采集时间（均为 `2026-07-16/17`）。其余 2,027 条在
源工作簿中 `收录时间` 为空，为跑通多观测窗路径，按 `CRC32(job_code)` 确定性三分到
`2026-06/07/08`，统一标记 `time_quality_code='synthetic_window_spread'`。

因此：

- **当前的 `budding` / `emerging` 分档不是市场结论**，只证明分档链路可用。
- 合成记录可随时筛出：`where time_quality_code='synthetic_window_spread'`。
- 聚类侧的近期活跃度与时间跨度只统计 `source_collected`，不受合成日期影响。
- 要获得真实分档，需要跨月真实采集：两个月度窗口达到 `budding`，三个才够 `emerging`。

技术里程碑来自 `embodied-job-evolution-lab` 的人工整理摘要，数据源
`milestone_curated_lab` 标记为 `curated` / `secondary_summary`、可靠度 60，以区别于
采集原文；其中 48 条无任何日期线索，仅估算年份（`data_origin_code='estimated_date'`）。

## 尚未完成或采用降级的部分

| 优先级 | 边界 | 当前处理 | 主要影响 |
| --- | --- | --- | --- |
| P0 | 长任务异步化 | 采集、OCR、聚类等仍由同步接口或 CLI 执行 | 大批量任务会占用请求进程 |
| P0 | 生产认证授权 | 有 JWT 基础能力，部分审核仍兼容 `X-Reviewer-Code` | 不能直接用于多租户或正式权限审计 |
| P0 | 官方质量指标 | 有自动化测试和候选标注集，但缺专家冻结金标准 | 不能宣称抽取、匹配达到正式 90% 指标 |
| P0 | 生产部署防护 | Compose 使用开发默认口令，Key 由本地 `.env` 注入 | 上线前必须更换密钥、加 TLS、备份和监控 |
| P0 | 真实时间序列 | 只有 1,691 条 JD 带真实采集时间且集中在两天，多观测窗靠合成日期跑通 | 分档与演化只可演示；`modified`/`weakened` 能力差异尚未在真实数据上出现 |
| P1 | 推演评分区分度 | 市场支撑饱和阈值偏低（JD 8 / 企业 5），重合度受单技术词岗位污染 | 高证据候选易同分；24 个候选被误判 `existing_role` 而失去发布资格 |
| P1 | 语料与词表范围 | 词表限定具身智能领域，语料含大量通用制造与职能岗 | 57% 的 JD 抽不出技术词属预期行为，不宜按覆盖率考核抽取质量 |
| P1 | 对象存储与事件总线 | 文件走本地路径，无 S3/Outbox | 多实例扩展和最终一致性能力有限 |
| P1 | 图社区算法 | 技术共现社区使用规则分组回退，关系图使用领域簇布局 | 不等同于 Leiden 等统计社区发现 |
| P1 | OCR 与文件安全 | 文本 PDF/DOCX/TXT 可解析；扫描件提示失败；无真实病毒引擎 | 扫描简历需先转为可检索文本 |
| P1 | 数据治理写操作 | 技术候选词池、完整 JD 在线编辑、系统设置页尚未开放 | 复杂治理仍依赖脚本和数据库流程 |
| P1 | 指标持久化 | L2 热力指标落库，L1/L3 为运行时投影 | L1/L3 历史结果不可离线回放 |
| P2 | LLM 可用性 | 无 Key 或调用失败自动退回规则表达/解释 | 机械评分和事实不受影响，语言质量会下降 |
