# 具身智能岗位能力图谱系统 — 项目设计方案

> 赛题：XH-202621 多源异构数据驱动岗位和能力图谱构建与动态演化分析  
> 领域聚焦：具身智能  
> 版本：v1.0（头脑风暴定稿）  
> 日期：2026-08-08

---

## 一、系统总览

### 1.1 核心定位

面向具身智能领域，构建"数据驱动 + 大模型 + 知识图谱"的全流程闭环系统，实现从数据采集到人岗匹配的完整链路。

### 1.2 全流程闭环架构

```
┌─────────────────────────────────────────────────────────────────┐
│                        全流程闭环系统                              │
│                                                                   │
│  模块1          模块2              模块3         模块4      模块5  │
│  多源数据  →  新岗位发现/     →  能力图谱  →  简历解析 → 精准匹配 │
│  采集          既有岗位更新        动态构建                 差距分析 │
│                                                                   │
└─────────────────────────────────────────────────────────────────┘
```

### 1.3 技术方向

- **数据驱动**：多源异构数据采集与清洗
- **大模型**：LLM语义分析、结构化提取、对话交互
- **知识图谱**：岗位-能力关系建模与可视化

## 二、模块1：多源数据采集

### 2.1 数据来源

| 来源类型 | 目标 | 说明 |
|---------|------|------|
| 招聘网站 | 在聘岗位JD | 企业→在聘岗位列表→岗位详情（最多一层深入） |
| 企业官网 | 行业动态 | 技术发布、产品更新等 |
| 政府网站 | 政策/行业报告 | 产业规划、标准发布等 |
| 用户手动输入 | 补充数据 | 支持手动传入文档/文本 |

### 2.2 爬取机制

- 用户维护**爬取对象表**（URL、频率、类型、状态）
- 系统**定时自动爬取**获取增量内容
- **增量检测**：基于内容hash/时间戳判断是否为新内容
- 爬取结果经基础清洗后进入LLM语义分析

### 2.3 LLM语义分析 → 三类素材提取

爬虫采集的增量内容经LLM语义分析后，提取为三类标准化素材：

| 素材类型 | 内容 | 用途 |
|---------|------|------|
| 岗位JD | 岗位名称、职责、技能要求、来源等 | 岗位聚类、能力需求分析 |
| 技术词 | 术语名称、分类、出处、上下文 | 能力图谱构建、缺口检测 |
| 技术里程碑 | 事件、技术方向、时间、影响 | 触发岗位更新、趋势判断 |

> 注：具体字段定义待后续讨论确认（见TODO文档）

### 2.4 数据质量保障

- 去重：内容相似度检测，避免重复入库
- 时效性：记录采集时间，支持时间衰减分析
- 溯源：每条数据保留原始来源URL

## 三、模块2：新岗位发现与既有岗位能力更新

### 3.1 新岗位发现

#### 触发机制：岗位缺口检测算法

基于三个信号综合判定是否存在新岗位缺口：
1. **技术词信号**：某些技术词组合频繁共现但无对应岗位覆盖
2. **里程碑信号**：关键技术里程碑已达成，暗示新岗位可能出现
3. **JD覆盖率**：现有技术词组合在已有JD库中的覆盖程度

```
判定逻辑：
IF 技术词组合频率 > 阈值 
   AND 相关里程碑已达成 
   AND JD覆盖率 < 阈值
THEN → 触发新岗位发现流程
```

> 注：覆盖率具体计算方式待确认（见TODO文档）

#### 岗位定义生成：两阶段策略

**阶段一：算法 + LLM 生成岗位卡片**

| 字段 | 来源 |
|------|------|
| 岗位名称 | LLM基于技术词组合生成 |
| 核心职责 | LLM生成（1-2句概括） |
| 必备技能 | 算法匹配的技术词 |
| 加分技能 | 关联但非核心的技术词 |
| 关联里程碑 | 触发本次发现的事件 |
| 置信度评分 | 算法判定 |
| 典型行业应用场景 | LLM补充 |

**阶段二：用户按需细化**
- 用户确认岗位卡片后，可选择进一步细化为完整JD
- 支持人工编辑优化

#### 审批流程
- 系统自动生成 → 用户审核确认/修改 → 入库

### 3.2 既有岗位能力动态更新

#### 核心机制：JD聚类驱动

```
初始状态：预定义标准岗位库（岗位聚类）
    ↓
新JD进入 → 提取技术词 → 计算与现有聚类的相似度
    ↓
┌─ 相似度高 → 归入现有聚类，更新该聚类能力集
├─ 相似度中 → LLM研判归属
└─ 相似度低 → 候选新聚类 → LLM评估
     ├─ 评分高 → 自动创建聚类
     └─ 评分低 → 进入用户审批队列
```

#### 聚类特征
- 分类标准与技术关键词分类保持一致，固定不增减
- 初始化时全量聚类，后续增量更新

#### 能力更新检测

| 检测维度 | 方法 | 输出 |
|---------|------|------|
| 新增能力 | 新JD中首次出现在该聚类的技术词 | 能力新增事件 |
| 淘汰能力 | 老JD高频但新JD消失的技术词（时间衰减） | 能力淘汰预警 |
| 热度变化 | 聚类下JD数量趋势 | 岗位热度指标 |
| 里程碑联动 | 里程碑事件影响相关聚类技术词分布 | 能力需求调整 |

#### 更新输出

每条能力变更包含：
- 变更类型（新增/删除/修改）
- 具体能力项
- 更新说明（为什么变化）
- 数据源（证据来源）
- 时间戳

## 四、模块3：能力图谱动态构建

### 4.1 图谱视图类型

| 图谱类型 | 数据源 | 展示内容 |
|---------|--------|---------|
| 能力热力图 | 技术词频率统计 | 近期引用频次 + 趋势 |
| 岗位-能力关联图 | 聚类×技术词关联表 | 全局关联关系、聚集程度 |
| 聚类能力需求图 | 选中聚类的能力集 | 特定岗位聚类的能力需求 |
| 技术演进图 | 技术词时间戳记录 | 技术新增/淘汰时间线 |
| 全景图谱 | 全量数据 | 按技术栈/级别切换视图 |

### 4.2 视图切换

- **技术栈切换**：按技术词分类标签过滤节点/边
- **级别切换**：按能力等级字段过滤（初级/中级/高级/专家）
- **聚类选择**：聚焦某个岗位聚类的子图

### 4.3 渲染方案

- 使用现有图谱渲染引擎（推荐 AntV G6）
- 不自行编写底层渲染逻辑
- 支持力导向布局、层级布局、径向布局

### 4.4 性能优化

- 分层加载：初始加载聚类级概览，点击展开细粒度
- 按需API查询：避免一次性加载全量数据

## 五、模块4：简历解析

### 5.1 多模态输入

支持格式：PDF、DOC/DOCX、TXT、手动文本输入

### 5.2 解析流水线

```
多格式输入
    ↓
文本提取层（格式解析 → 纯文本）
    ↓
结构化提取层（LLM提取基本字段）
    ↓
LLM对话补全（可选，追问模糊信息）
    ↓
语义分析层（LLM深度理解）
    ↓
求职者画像输出
```

### 5.3 求职者画像：双层结构

#### 第一层：结构化数据（硬性匹配用）

| 字段 | 说明 |
|------|------|
| 求职意向岗位 | 目标岗位名称/方向 |
| 技术能力列表 | 提取的技术关键词 + 熟练度评估 |
| 工作经历 | 公司、岗位、时间、核心职责 |
| 项目经验 | 项目描述、技术栈、个人贡献 |
| 教育背景 | 学历、专业、学校 |
| 工作年限 | 总年限 + 相关领域年限 |

#### 第二层：语义画像（软性匹配 + 差异化展示）

| 字段 | 说明 |
|------|------|
| 能力深度评估 | 基于项目描述判断技术实际掌握深度 |
| 工作风格 | 协作型/独立型/领导型/执行型等 |
| 发展意愿与路径 | 从经历轨迹推断职业发展方向 |
| 学习潜力指标 | 技术栈跨度、新技能获取速度 |
| 综合优势摘要 | LLM生成的个人亮点概括 |

> 注：语义画像限定在工作风格维度，不做深层人格判断

### 5.4 LLM对话交互机制

- LLM解析简历后若发现信息不足/模糊，可向求职者提问
- 求职者回答后LLM更新画像
- 对话轮次上限：3-5轮
- 目的：提升解析准确率 + 丰富语义画像 + 增强用户体验

### 5.5 准确率目标

- 简历提取准确率 ≥ 90%
- 验证方式：文本提取正确率均值（对比标注数据）

## 六、模块5：人岗匹配与差距分析

### 6.1 多维度综合匹配模型

```
总匹配度 = 硬性匹配分 × W1 + 软性匹配分 × W2 + 发展潜力分 × W3
```

| 维度 | 匹配方式 | 说明 |
|------|---------|------|
| 硬性技能匹配 | 技术词集合对比 | 必备/加分技能覆盖率 |
| 技能深度匹配 | LLM语义比对 | 实际使用深度 vs 岗位要求深度 |
| 经验匹配 | 规则+语义 | 行业经验、岗位经验年限 |
| 软性匹配 | LLM综合评估 | 工作风格与岗位特性契合度 |
| 发展潜力 | LLM评估 | 技能迁移性、学习轨迹方向 |

### 6.2 差距分析输出

```
匹配结果
├── ✅ 匹配项（已具备能力）→ 标注匹配强度
├── ❌ 缺失项（完全不具备）→ 按重要性排序
├── ⚠️ 不足项（有但深度不够）→ 标注差距程度
└── 📋 LLM改进方案
    ├── 短期提升（1-3月）
    ├── 中期提升（3-6月）
    ├── 长期规划（6-12月）
    └── 推荐学习路径（基于图谱技能关联）
```

### 6.3 学习路径规划

- 与能力图谱联动：图谱中技能A是技能B的前置依赖 → 先补A再补B
- 按优先级排序：根据目标岗位权重确定学习顺序
- 可推荐并行学习项：无依赖关系的技能可同步学习

### 6.4 准确率目标

- 人岗匹配准确率 ≥ 90%
- 验证方式：每份测试简历预定义匹配岗位范围，判断系统推荐是否在范围内

## 七、创新性设计

### 7.1 多源数据清洗与交叉验证

| 问题 | 解决方案 |
|------|---------|
| 时滞 | 时间戳记录 + 时间衰减模型 + 增量爬取 |
| 噪声 | 爬虫后基础清洗 + LLM语义过滤 |
| 抄袭/重复 | 内容相似度检测去重 |
| 通胀 | 技术词频率+时间趋势交叉验证，区分真实需求vs跟风 |

### 7.2 幻觉防控机制

| 环节 | 防控措施 |
|------|---------|
| LLM提取 | 结构化Prompt + 输出格式约束 |
| 数据溯源 | 所有LLM输出关联原始数据URL |
| 置信度评分 | 算法对LLM输出进行可信度打分 |
| 人工审核 | 关键节点（新岗位创建、能力更新）设审批环节 |
| 交叉验证 | 同一信息在多源中验证一致性 |

### 7.3 对话式信息补全

- LLM主动追问模糊信息，而非猜测
- 用户参与确认，减少幻觉风险
- 提升数据质量的同时增强用户参与感
