## 1. 任务定位

把「技术证据数 < N 的低信息量 JD」挡在聚类之外:它们不参与聚类、不产生簇,
进入「待治理池」。这一刀解决两个问题(07 任务书任务组 3 机械版 + 4.2):

- 3,534 份可聚类 JD 里混入大量 CNC/采购/QE/丝印/销售/招聘岗(非具身智能技术岗)
- 技术词 <2 的 JD 注定匹配不上,是 1,630 个单例簇(77.8%)的主要来源

已量化的过滤效果(基于当前 v1.1 词表,**词表修复后需重算**,本分支不重算):

| 技术证据门槛 | 可聚类 JD |
| --- | ---: |
| ≥0(现状) | 3,534 |
| ≥1 | 1,509 |
| **≥2(暂定默认)** | **897** |
| ≥3 | 569 |

### 明确不做的事

- **不动聚类算法本身**:`clustering/algorithm.py` 的相似度通道、阈值、权重归窗口 C
  (`feat/clustering-rework`)。你只在聚类**入口**做过滤
- **不动岗位晋升逻辑**:`clustering/service.py` 的 `_propose_role` / 谱系 / 演化事件不改。
  如果实现中发现必须改它们才能完成过滤,停下,报告主控
- 不做 LLM 语义过滤版(那是后续评估增量的可选项,参照
  `biz_llm_technology_reassessment_run` 的 materialize 模式,不在本分支)
- 不在共享 Docker MySQL 上跑 `cluster_jobs` 等正式管线(窗口 A 运行规则)
- 不标定最终 N 值(默认 2,标记为临时)

## 2. 设计指导(已定的口径,实现细节留给你)

1. **过滤位置**:`clustering/service.py` 聚类入口(`run_full_clustering` /
   `_execute_clustering_run` 一带,先读代码定夺)。输入是特征快照
   (`JobClusterFeatureSnapshot`),过滤依据是**该 JD 的 accepted 技术证据数**。
   注意核对口径:实现对「≥2 → 897」这个数,对不上要在交付说明里报告口径差异
   (计数来源候选:特征快照 payload 的 `technology_weights` 条数 vs
   `biz_job_requirement` 关联 accepted 评估数,选可解释、可复现的那个)。
2. **参数化**:`ClusteringParameters` / `DEFAULT_PARAMETERS` 新增
   `min_technology_evidence_count`(默认 2),写入 `run.parameter_json`。
   参数不得硬编码(07 任务书约束 4)。
3. **待治理池(轻量实现,不建新表)**:
   - run 的 `quality_metric_json` 记录:`filtered_job_count`、阈值、被过滤 JD 的
     证据数分布(0/1 各多少)等聚合统计
   - 被过滤集合可由 `parameter_json` 阈值 + 输入确定性重算,不需要落大 JSON 列表
   - 如你认为确需落明细,先在交付说明里论证再动手
4. **版本升级(必须)**:过滤改变聚类行为,`ALGORITHM_VERSION` 必须升版
   (现为 `baseline_sparse_multiview_v1`,建议 `baseline_sparse_multiview_v2`),
   否则历史运行的重放缓存串味(07 任务书约束 3)。
5. **重放兼容**:确认 `input_snapshot_hash` 口径覆盖过滤参数的影响路径——
   同输入同参数必须同结果(约束 2)。已有重放回归测试,别破坏。

## 5. 约束与陷阱

1. **不跑共享库正式管线**(parse/cluster/discover/LLM):验证只用 pytest + 合成夹具。
   共享 MySQL 的执行权在窗口 owner 手里(排程规则,详见 07 任务书与主控排程)
2. **不动 `algorithm.py` 与晋升逻辑**:越界会与窗口 C 冲突,主控会打回
3. **升版重放缓存**:见 2.4;曾有「改输入却命中重放缓存」的 bug,已修并有回归测试
4. **只格式化自己改动的文件**;CI 只跑 `ruff check`
5. 不在 `main` / `codex/redesign-from-scratch` 提交;完成后停下等审查,不合并
6. 本地 Python 默认连 SQLite——单测本来就跑 SQLite,没问题;但**不要**以为自己在验证真实数据
