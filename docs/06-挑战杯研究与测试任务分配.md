## 一、分配原则

本轮不按“前端、后端、文档”割裂分工。每名成员完整负责一个核心模块，并同时完成两类工作：

1. **研究工作**：读懂当前代码和数据，明确算法输入、公式、阈值、输出、证据边界和降级策略。
2. **验证工作**：实际运行系统，建立测试集，输出指标、错误案例和可复现实验记录。

如果 PPT 设想与当前实现不一致，负责人必须给出明确处理结论：

- 修改 PPT，使描述符合当前实现；
- 补充研究说明，将其标记为后续规划；
- 或提交代码改进 PR，使实现达到材料中的合理要求。

任何成员不得把合成数据结果、代码中的默认值或 PPT 中的目标值直接写成正式测试结论。

### 研究目标

理解系统如何从真实 JD、技术成熟度、市场支持和岗位覆盖缺口中发现候选岗位，并说明候选如何经过人工审核成为正式岗位。

当前实现不是 PPT 中简单的“产业技术热度 ÷ JD 频次”，而是八个正向维度与五类惩罚项的组合：

- 技术相关性、任务缺口、社区凝聚度、市场支持；
- 技术成熟度、时间增长稳定性、证据完整度、新颖性；
- 单企业、单来源、营销信息、证据矛盾、未验证技术惩罚。

当前成熟阶段为 `potential / budding / emerging` 三档，PPT 为 E→A 五级潜水机制。负责人需要比较两者并形成决定：保留三阶段并修改 PPT，或设计可验证的五级映射并改进实现。

### 测试任务

1. 从当前数据中选择 20–30 个候选组合，人工判断其是否具备独立岗位意义。
2. 分别运行自动发现、技术词定向和岗位名称核验三种模式。
3. 记录候选得分、成熟阶段、风险标记、企业数、来源数和人工结论。
4. 计算 `Precision@K`、人工通过率、证据完整率和风险标记命中率。
5. 构造单企业、单来源、无应用证据和证据矛盾案例，验证惩罚与降级是否生效。
6. 选择一个候选，完成“发现—定义—审批—正式入库”的完整演示。

### 验收标准

- 算法说明能够逐项对应代码，不使用无法复现的公式。

- 明确区分算法候选、人工审批结果和正式岗位。
- 不把单个公司或单条 JD 当作成熟新岗位证据。

### 负责人信息

- 计划完成：待填写
- Issue：待填写

### 研究目标

理解 JD 多视图聚类、稳定簇、岗位版本、能力重要度和演化事件如何组成“既有岗位动态更新”闭环。

当前聚类使用标题、职责、能力、技术域、场景和级别六个视图。其中场景通道在当前算法中仍为降级值，来源时间也主要覆盖两天，所以趋势统一标记为 `insufficient_history`。负责人必须如实说明这一边界。

建议研究以下更新机制：

- 当前窗口与历史窗口的能力覆盖率和权重差；
- 多企业、多来源最低支持量；
- 新增、增强、减弱、删除能力的不同阈值；
- 移动平均、Jensen-Shannon Divergence 或变点检测的适用性；
- 防止技能在版本间反复增删的迟滞机制；
- 岗位拆分、合并和成员迁移时稳定编码的处理。

### 代码阅读范围

- `backend/app/modules/clustering/algorithm.py`
- `backend/app/modules/clustering/service.py`
- `backend/app/modules/clustering/models.py`
- `backend/app/modules/graph/service.py`
- `backend/tests/test_clustering_algorithm.py`
- `backend/tests/test_clustering_service.py`

3. 验证新增、增强、减弱和删除能力是否符合人工判断。
4. 计算变化识别准确率、误报率、岗位簇稳定度和版本可追溯率。
5. 重复执行相同输入，验证解析、聚类和版本生成是否幂等。
6. 构造岗位拆分、合并和灰区成员案例，检查稳定簇关系是否合理。
7. 输出一个可用于 P12、P14、P18 的完整演化案例。

### 交付物

- 能力变化判定公式、阈值和伪代码。
- 至少一个既有岗位跨期演化案例。
- 稳定性、误报和幂等测试报告。
- P12、P14、P18 对应图表、时间线和答辩话术。
- 如现有趋势判定不足，提交窗口、阈值或变化检测改进 PR。

### 验收标准

- 不能用两天数据宣称形成长期趋势。
- 算法簇、候选岗位和正式岗位必须分开描述。
- 所有能力变化必须包含来源、时间和前后版本。
- 同一输入重复运行不得制造无意义的新版本。

### 研究目标

梳理数据从文件准入、Raw 账本、去重、来源评分、技术抽取、DeepSeek 复核到人工审核的完整可信链路。

PPT 规划了企业、专利、岗位、人才、高校和技术词六库。当前 MVP 稳定覆盖岗位、技术词和人才画像，企业、专利、高校尚未形成完整真实数据闭环。当前图谱事实存储在 MySQL，也没有完整 Neo4j 和通用 RAG 系统。负责人必须把“已实现、降级实现、规划能力”分开表述。

幻觉防控应整理为三层：

1. 输入层：内容哈希、重复检测、来源独立性、时效、矛盾和置信评分。
2. 生成层：闭集技术编码、冻结事实快照、JSON Schema 和逐字证据约束。
3. 输出层：结果校验、审计记录、版本留痕和人工审批。

## 八、统一测试规则

- 先冻结测试集和标签，再运行算法，禁止根据结果修改标签。
- 正式指标至少包含 Precision、Recall、F1 和混淆矩阵，不只报告 Accuracy。
- 记录算法版本、数据版本、参数、随机种子和运行时间。
- 双人标注必须保留各自原始标签、争议项和仲裁结果。
- 合成数据只能作为单元测试或边界回归，不能作为挑战杯正式准确率。
- PPT P22 中的 `92% / 94% / 91%` 在正式测试完成前统一标记为“目标值/待验证”。
- 任一指标低于目标时，应报告错误类型并提出改进，不得选择性删除失败样本。
