# 新岗位发现实现计划

## 目标与验收口径

**目标**：发现「研究/专利侧已成形、招聘侧尚未出现」的能力组合，并把它们呈现为
可审阅的新岗位候选。

**验收口径明确接受不确定性**：不要求每条都准，要求**每条都标明置信等级与依据**，
让审阅者能自行判断。这与本项目此前的口径不冲突——不确定的可以出，
**冒充确定的不可以**。

**当前状态**（2026-08-26）：

| 项 | 数值 |
| --- | ---: |
| 上游语料（arXiv + 专利，可用于共现） | 2,426 篇 |
| 上游涉及 L3 技术点 | 174 个 |
| 其中 JD 侧完全未提及 | **60 个** |
| JD 语料 | 3,718 份，其中有技术命中 1,707 份 |
| JD 覆盖 L3 技术点 | **130 / 242** |
| 缺口技术对产出 | **2 对，且参考区间均已过期** |

## 已定位的根因

### 根因 A：JD 语料混着大量非技术岗

零命中的 2,011 份 JD 逐层拆开：

```
零命中 2,011
├─ 570   职能门已判为非具身职能（商务 195 / 制造 185 / 产品运营 182 / IT 运维 8）
└─ 1,441 职能门未拦下
   ├─ 1,256 中文、正文完整——但实际是子公司管理总监、客服质检培训专家、
   │        品牌总监、仓库管理员、投放获客经理、内审高级经理……
   │        **仍非技术岗，只是职能门规则没覆盖这些词**
   ├─ 144   正文过短（<150 字）
   └─ 34    英文 JD
```

**判定：不是技术词命中难度问题，是语料构成问题。** 数据实为「具身智能企业发布的
全部岗位」（含 HR、财务、客服、仓管、品牌、普工），而非「具身智能技术岗位」。
技术词表匹配不到它们是正确行为。

### 根因 B：把「JD 提及过少」一律当噪声删掉，删错了

缺口分析的三道过滤中，「JD 中提及过少」剔除了 192 对。设这道过滤的初衷是挡住
语料域偏离（arXiv 的无人机研究与具身智能招聘市场无关），但它同时挡住了另一种
情形：**该技术在招聘市场上还没出现——而那恰恰是新岗位信号本身**。

两种情形被混为一谈，且系统替审阅者做了删除决定。**应改为分级输出，不是过滤。**

### 根因 C：专利语料只用了中文标题

工作簿含 `英文标题` 列而导入时未使用。当前英文别名覆盖率已达 91%，
英文标题是可直接利用的第二段文本。专利现有 4,206 件仅 377 件命中 ≥2 技术点（9%），
主因是中文标题仅 18–19 字。

## 实施阶段

每阶段都写明**降级方式**：该阶段失败时如何退回，以及退回后整体还能交付什么。

### S1　专利英文标题接入

把 `英文标题` 与中文标题一并送入匹配。

- **预期**：专利可用文档数上升；英文别名（623 条）得以在专利语料上发挥作用
- **判据**：可用文档数较 377 提升 ≥50%
- **降级**：若英文标题大面积为空或为机器直译导致命中反而变噪，
  回退为仅用中文标题，并在语料清单中记录该结论。整体流程不受影响

### S2　职能门规则扩充

补齐漏掉的非技术职能词（总监类、客服、品牌、仓储、审计、投放获客、
质检培训、行政法务采购等）。

- **预期**：语料分母变准，期望共现数的估计随之变准，S3 的统计判据更灵敏
- **判据**：零命中 JD 中「职能门未拦下」的比例由 72% 降到 40% 以下
- **风险**：扩得过头会误伤技术岗
- **降级**：**职能门的扩充只用于统计口径修正，不删除任何 JD 数据**。
  若发现误伤，回退规则即可，历史抽取结果不受影响。这一点由实现方式保证——
  职能判定是标注而非过滤

### S3　缺口对改为分级输出（核心）

废弃「三道过滤后只留确定的」，改为**全部输出并分级**：

| 等级 | 判据 | 含义 |
| :---: | --- | --- |
| **A** | 两侧技术在 JD 中均常见，独立性下期望共现 ≥2 而实测为 0 | 缺口最可信：市场在招这两个方向，却从不合招 |
| **B** | 两侧技术在 JD 中均出现过，但期望共现不足 2 | 缺口存在，但样本量不足以排除偶然 |
| **C** | 至少一侧技术在 JD 中从未出现 | **可能是最新的信号，也可能是语料域偏离**——两种解释本系统无法区分，交审阅者判断 |
| 剔除 | 同一 L2 的同族近义对 | 同一件事的两种说法，不构成组合 |

C 级是本次口径变化的关键：此前它被当作噪声删除，实际上「该技术在招聘市场上
尚未出现」既可能是语料问题，**也正是新岗位的定义本身**。

- **判据**：A+B+C 合计 ≥30 对，其中 A 级 ≥3 对
- **降级**：若 A 级为 0，仍交付 B/C 级并在界面显著标注「无高置信条目」。
  绝不为凑数把 B/C 冒充 A

### S4　技术对扩展为能力组合并生成候选

把缺口技术对扩展成 2–4 个技术的能力组合（沿用现有闭项集逻辑），
由 LLM 生成岗位名与描述，落为独立的候选类型。

- **判据**：生成的候选带完整证据链（上游文档编号、共现次数、锚点日期）
- **降级**：LLM 不可用时退回机械命名（技术名以「·」连接），
  已有的 `_mechanical_name` 即为此准备。功能不阻塞

### S5　前台呈现

在新岗位发现页新增独立分区，与现有的「岗位库更新迭代」类候选**分开陈列**，
避免两类性质不同的产出混淆。

- 每条必须同屏显示：置信等级、上游证据（共现次数与首现日期）、
  JD 侧覆盖情况、参考区间及其「外部先验、未经验证」标注
- **降级**：若 S3/S4 产出为空，分区显示空状态并说明当前语料条件下无产出，
  不隐藏该功能——空状态本身是有信息量的结论

## 不做什么

- **不做时间预测的强断言**。U-3 回测已否定「上游领先招聘若干年」
  （提升度不随时点前移下降）。参考区间只作为文献先验呈现，
  且必须标注本系统无法验证
- **不为提高产出而放宽同族近义对的剔除**。那类对是词表结构造成的假象，
  放进来只会稀释真实信号
- **不把 C 级条目描述为「发现的新岗位」**。它们是待核查的信号
