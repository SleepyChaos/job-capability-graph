## 推荐并行分工

第一轮可由 5 条工作流并行推进：

1. 后端 A：`P0-01`，完成后协助 `P0-05` 的鉴权场景。
2. 后端/平台 B：`P0-02` → `P0-06`。
3. DevOps：`P0-03`，同时准备 `P1-06` 的存储环境。
4. 算法/数据：`P0-04`，随后进入 `P1-02`。
5. 前端：`P0-05` 与 `P1-03`，但鉴权 E2E 等待 `P0-01` 接口稳定。

## 统一完成标准

每个任务的 PR 至少满足：

- 从最新 `codex/redesign-from-scratch` 建分支，命名 `feat/<task-id>-short-name`。
- 包含迁移、配置或运维变更说明；不得提交密钥和未脱敏人才数据。
- 新逻辑有自动化测试，后端 Ruff/pytest、前端 build 和相关测试全部通过。
- API 或数据口径变化同步更新本目录中的唯一主题文档。
- PR 描述包含验收步骤、截图或接口样例、风险和回滚方法。
- 至少一名非作者评审通过后再合并。

任务负责人只需在表格中把“状态”改为“进行中（姓名 / Issue / 日期）”；完成合并后改为“已完成（PR / 日期）”。
