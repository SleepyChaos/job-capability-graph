## 1. 任务定位

为论文核心实证——「技术结构 → 岗位」推断能力验证——搭建可复现的实验基础设施。

实验设计(已定,不要改设计本身,只做工程实现):

- 随机遮蔽 20% 的正式岗位(**仅选技术词 ≥2 的**),在遮蔽状态下跑新岗位推演,
  检查被遮蔽岗位能否作为高分候选被重新发现
- 指标:Recall@K(K=10/25/50/100)、被遮蔽岗位的候选排名分布、
  候选与被遮蔽岗位的技术集合 Jaccard、与随机排序基线的对比
- 冻结要求:遮蔽比例、随机种子、算法版本、输入快照哈希必须进实验记录

**为什么现在只能准备不能执行**:抽取质量未修复(任务书红线:评估完成前不得下研究结论),
现在跑出来的 Recall 数字没有意义,还会污染共享库的推演运行历史。

### 明确不做的事

- 不执行任何正式 `run_discovery`(共享库运行权规则)
- 不基于现有数据出任何实验结论或数字
- 不改 discovery 的算法/评分逻辑(`discovery/algorithm.py`、`service.py` 的打分、
  分类阈值都不动)——你只调用它
- 不做「提高候选粒度到技术组合」(那是任务组 5 的活)

## 3. 实施步骤

1. 读代码:`discovery/service.py` 的 `run_discovery` 签名与参数传递、
   `_role_capability_profiles`、候选持久化结构(`discovery/models.py`)、
   `tools/discover_roles.py` 的调用方式、现有测试 `tests/test_discovery_service.py` 的夹具
2. 实现实验脚本 `tools/run_holdout_experiment.py`:
   - **遮蔽集生成**:从正式岗位中选「版本技术词 ≥2」者,按 `mask_ratio`(默认 0.2)与
     `seed` 采样。**遮蔽集合必须由(输入集合 + mask_ratio + seed)确定性导出**,
     不允许 hardcode 名单;同时输出 manifest(遮蔽 role_ids、seed、ratio、
     输入快照哈希、算法版本,连同 sha256)落盘供审计
   - **推演调用**:以 automatic 模式调 `run_discovery`,parameters 带
     `excluded_role_ids=遮蔽集`。脚本只封装调用与结果读取,不改推演逻辑
   - **指标计算**:Recall@K(10/25/50/100)、被遮蔽岗位在候选中的排名分布、
     候选 vs 被遮蔽岗位技术集合 Jaccard、随机排序基线(同种子)
   - **报告输出**:按模板写 `docs/reports/holdout实验报告_*.md` 或 JSON 结果文件,
     头部固定记录冻结字段(遮蔽比例/种子/算法版本/输入快照哈希/参数快照)
   - **防呆**:执行入口加确认参数(如 `--execute`),默认 dry-run 只打印将做什么,
     防止误触正式运行
3. 报告模板:`docs/reports/holdout实验报告模板.md`,字段与冻结要求对应
4. 单测(合成数据,参考 `test_discovery_service.py` 的造数方式):
   - 同 seed + 同输入 → 同遮蔽集合(确定性)
   - Recall@K / 排名分布 / Jaccard 计算正确性(构造已知排名的假候选验证数值)
   - 随机基线的构造正确(同种子可复现)
   - `excluded_role_ids` 确实把遮蔽岗位挡出画像池(合成小场景断言)
5. `pytest` 与 `ruff check` 通过
