# 测试、部署与运维

## 本地一键启动

```bash
git switch codex/redesign-from-scratch
docker compose up --build -d
```

新空库默认按以下顺序启动：

```text
MySQL 健康 → 恢复审计快照 → Alembic 到 head → 幂等补全 → API → Web
```

访问地址：

- Web：<http://127.0.0.1:8080>
- API 健康检查：<http://127.0.0.1:8000/api/v1/health>
- OpenAPI：<http://127.0.0.1:8000/docs>

```bash
docker compose ps
docker compose logs -f backend frontend
docker compose down
```

`down` 保留 MySQL 卷；只有明确需要重建数据时才应移除卷。

## 数据恢复与重建

默认恢复 `data/runtime/job-capability-graph-mysql-20260812.sql.gz`。该快照已在临时库验证可恢复，恢复结果包含 3,718 条 JD、803 条 LLM 审计记录、2,102 个最新聚类，并处于迁移 `20260812_0013`。

从项目核心 XLSX 重新构建空库：

```bash
RESTORE_RUNTIME_SNAPSHOT=0 docker compose up --build -d
```

重建只使用 `data/source/20260810/core`，不会执行外部数据包中的 SQL。若卷中已有表，恢复服务会跳过快照；因此切换恢复策略前要先确认卷状态，避免误以为数据已替换。

## DeepSeek 配置

密钥只放在不入库的根目录 `.env`：

```dotenv
APP_LLM_API_KEY=your-key
APP_LLM_BASE_URL=https://api.deepseek.com/v1
APP_LLM_MODEL=deepseek-chat
```

无 Key 或调用失败时系统返回规则文本。不要把 Key 写入 Compose、快照、日志、Issue 或测试夹具。
