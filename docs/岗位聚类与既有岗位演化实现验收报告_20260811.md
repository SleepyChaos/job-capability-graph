# 岗位聚类与既有岗位演化实现验收报告

日期：2026-08-11

阶段：可重放岗位聚类、稳定岗位候选与能力版本草稿（已完成）

## 1. 阶段结论

本阶段已把上一阶段生成的 3540 条可聚类 JD 特征转化为可重放、可解释、保留 Top-K 归属证据的岗位聚类结果，并为证据达到最低门槛的聚类生成稳定岗位候选、岗位版本、能力重要度、原文证据、演化变更草稿和人工审核任务。

算法聚类不等于正式岗位。当前 111 个稳定岗位候选全部处于待审核状态，正式激活岗位数量仍为 0。单例、灰区和证据不足的聚类不会自动晋升岗位，也不会进入后续“既有岗位覆盖”正式计算。

## 2. 聚类基线

### 2.1 输入与可重放性

聚类输入来自已完成的 JD 解析运行 `jdparse_8ad8184577692c219c983899`，每条输入绑定：

- JD 编码和正文版本；
- 聚类特征版本及特征哈希；
- 标题和职责词元；
- 已治理的标准技术词权重；
- T1–T7 领域分布；
- 岗位级别；
- 去重证据权重和时间质量。

运行保存算法版本、完整参数和输入快照哈希。相同输入、算法和参数再次执行会返回原运行，不会覆盖或重复生成聚类、岗位版本和审核任务。

### 2.2 算法与归属

首版算法为 `baseline_sparse_multiview_v1`。它复用了 main 分支“IDF 加权可解释基线”的思路，但没有复用全局变量、输入顺序生成 ID、删除旧结果或覆盖式成员关系。

相似度口径为：

```text
0.20 × 标题余弦
+ 0.30 × 职责余弦
+ 0.25 × 标准技术词余弦
+ 0.10 × T域余弦
+ 0.08 × 应用场景余弦
+ 0.07 × 岗位级别一致性
```

当前应用场景结构化特征尚未到位，该分量明确保存为 0，并在运行质量中标记 `scenario_feature_status=not_available`，没有把其他字段伪装成场景特征。标题特征会移除常见城市前缀、岗位编号和已单独表达的级别噪声。

首版门槛：

- 总分不低于 0.36：自动归入候选簇；
- 0.24–0.36：标记灰区并保留独立簇，等待后续校准或审核；
- 低于 0.24：创建新的算法簇，不强制塞入已有岗位；
- 每条 JD 保存最终簇、分项得分、初始归属置信度和 Top-3 候选。

## 4. 聚类版本和谱系

新增聚类运行、聚类版本、成员、T 域和谱系实体：

- 聚类版本保存稳定簇编码、中心、代表 JD、成员数、独立企业数和一致性；
- 聚类成员保存 Top-K、分项得分、灰区状态和代表成员标记；
- T 域关系按成员能力加权生成，保存领域得分和证据数；
- 首次运行的所有簇标记为 `born`；
- 后续运行通过成员 Jaccard 重叠执行一对一稳定簇延续；
- 聚类结果永不覆盖旧运行。

首版已经支持 `born/continued` 和稳定簇编码延续。复杂的 `split/merged/ended` 多对多谱系分类仍需在出现第二个真实周期后补齐验收，不能用同一批数据人为制造演化案例。

## 5. 稳定岗位与能力版本

只有满足以下条件的算法簇才生成稳定岗位候选：

1. 聚类状态为 active；
2. 至少 3 条真实 JD；
3. 至少 2 个独立企业；
4. 标题不是乱码或“未说明岗位”；
5. 聚类一致性达到最低门槛。

聚类和稳定岗位通过 `rel_job_cluster_role` 桥接，二者 ID 不混用。每个候选岗位生成版本 1，包含代表职责、级别分布、证据强度和标准技术要求。

能力长期重要度使用覆盖率、必需比例、企业多样性、来源多样性、近期活跃度、趋势和职责支撑计算；近期活跃度单独保存，不与长期重要度混成一个字段。技术要求可下钻到 JD 证据片段。

## 6. 时间边界与演化防误判

1599 条 JD 有源采集时间，但全部集中在 2026-07-16 和 2026-07-17 两天；其余 1941 条只有迁移接收时间。因此当前数据不能支持 90 天趋势、连续窗口滞回或技术淘汰判定。

系统执行以下保护：

- 迁移接收时间不作为招聘发布时间；
- 所有能力趋势标记为 `insufficient_history`；
- 趋势分不参与重要度正向贡献；
- 不生成任何 `removed` 能力变更；
- 初始版本只生成有真实证据的 `added` 草稿；
- 后续删除必须等待多个真实时间窗口和采集量稳定性检查。

本次生成 338 条初始 `added` 变更，均为待审核建议，不代表行业已经发生能力演化。

## 7. 审核发布闭环

每个岗位版本候选自动创建 `data_review/job_role_version` 审核任务，支持领取、通过、驳回和退回修改。审核动作保存审核人、评论、状态迁移和前后快照。

审核通过时在同一事务中：

1. 关闭上一正式版本；
2. 发布当前岗位版本；
3. 激活稳定岗位；
4. 发布对应演化事件；
5. 保留全部聚类、要求和证据历史。

审核接口继续使用开发期 `X-Reviewer-Code` 身份桥接；正式认证将在安全交付阶段替换。

## 10. 下一阶段

下一阶段进入新岗位发现与专项审批。它只能消费：

- 人工批准的稳定岗位版本；
- 人工验证的技术里程碑；
- 正式 JD 和标准技术词；
- 带 target_date 的可重放统计快照。

当前稳定岗位和技术里程碑的正式数量均为 0，因此可以先实现算法、运行、输入快照、机械岗位卡和专项审批结构，但不能在没有真实审核数据时宣称已经发现真实新岗位。
