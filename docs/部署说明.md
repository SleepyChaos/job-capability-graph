# 部署说明（阶段 6 交付物）

> 项目：多源异构数据驱动岗位和能力图谱构建与动态演化分析系统（赛题 XH-202621）
> 对应《开发文档.md》阶段 6：Dockerfile + 容器化部署

## 1. 架构

```
浏览器
  ├── http://localhost:3000  前端（Next.js standalone，容器 jcg-frontend）
  └── http://localhost:8002  后端 API（FastAPI，容器 jcg-backend，宿主 8002 → 容器 8000）
数据：SQLite unified.db（单一事实源，docker volume db-data 持久化，含 WAL）
```

- 前端在**浏览器端**直连 `http://localhost:8002`（`NEXT_PUBLIC_API_BASE` 构建时注入），
  因此后端必须暴露到宿主 8002 端口——与开发环境端口约定完全一致。
- 已接入 **DeepSeek**（OpenAI 兼容接口，模型 `deepseek-chat`）；未配置 `OPENAI_API_KEY` 时 LLM 链路自动降级为规则方案（聚类命名/岗位定义启发式），系统功能不受影响。

## 2. 快速启动

```bash
cd job-capability-graph
docker compose up -d --build
```

| 服务 | 地址 | 健康检查 |
|---|---|---|
| 前端 | http://localhost:3000 | 打开页面即验证 |
| 后端 | http://localhost:8002/api/health | `curl http://localhost:8002/api/health` → `{"status":"ok"}` |

停止：`docker compose down`（数据保留在卷中）；连同卷删除：`docker compose down -v`。

## 3. 可选配置（.env 文件或环境变量）

项目根 `.env`（如 LLM Key）在启动时自动加载，已设置的环境变量优先；`docker compose` 自动读取同目录 `.env`。

| 变量 | 默认 | 说明 |
|---|---|---|
| `NEXT_PUBLIC_API_BASE` | `http://localhost:8002` | 前端构建时注入的后端地址 |
| `OPENAI_API_KEY` | 空 | 配置后启用 LLM 增强（DeepSeek / 其他 OpenAI 兼容网关） |
| `OPENAI_BASE_URL` | `https://api.deepseek.com/v1` | OpenAI 兼容网关地址 |
| `LLM_MODEL` | `deepseek-chat` | 模型名（DeepSeek 亦可选 `deepseek-reasoner`） |

## 4. 镜像构建（单独）

```bash
# 后端
docker build -f backend/Dockerfile -t jcg-backend .
docker run -d -p 8002:8000 -v jcg-db:/app/db jcg-backend

# 前端
docker build -f frontend/Dockerfile --build-arg NEXT_PUBLIC_API_BASE=http://localhost:8002 -t jcg-frontend frontend
docker run -d -p 3000:3000 jcg-frontend
```

## 5. 数据说明

- `db/unified.db` 首次构建即包含完整数据主体：岗位 6,793 / 技能词 505 / 图谱边 16,925 / 聚类 1,680 / 简历 175。
- 容器内写入（简历上传、审核、快照差分）落在 `db-data` 卷，`docker compose down` 不丢失。
- 如需重置为出厂数据：删除卷后重新 up（`docker compose down -v && docker compose up -d --build`）。

## 6. 生产注意事项

- 单机 SQLite 适合演示与小型部署；大并发需迁移 PostgreSQL（仅改 db 层连接，业务 SQL 为标准语法）。
- 容器内未启用 `--reload`（生产模式）；本地开发请用 `scripts/start_dev.sh`。
