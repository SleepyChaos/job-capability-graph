# Docker 开发说明

## 目标

Docker Compose 运行前端、FastAPI、MySQL 8 和一次性数据初始化服务。初始化只使用项目自己的 Alembic 迁移与核心 XLSX 导入链路，不执行数据包目录中的旧 SQL。

## 启动

在仓库根目录执行：

```bash
docker compose up --build
```

首次启动顺序为：

```text
MySQL 健康检查 → Alembic migrate → bootstrap 导入/解析/聚类/审批 → backend → frontend
```

前端地址：`http://127.0.0.1:8080`

后端健康检查：`http://127.0.0.1:8000/api/v1/health`

`bootstrap` 服务是幂等的。它会：

1. 创建开发期 `reviewer-demo` 和 `admin-demo`；
2. 暂存并发布技术词主数据 v1.1；
3. 暂存并发布 3,718 条核心 JD；
4. 运行 JD 结构化解析和可重放岗位聚类；
5. 通过项目审核服务审批当前所有岗位版本审核任务，并写入审核动作。

## 清空并重建 MySQL

如需从零验证迁移和数据导入，先删除本项目 Compose 卷：

```bash
docker compose down -v
docker compose up --build
```

删除卷会清空该 Compose 项目的 MySQL 数据，确认目标为本项目的 `job-capability-graph_mysql-data` 后再执行。

## SQLite 快照

`data/runtime/job-capability-graph-runtime.db` 是已完成导入和审批的 SQLite 开发快照，供离线核对使用。Docker Compose 使用 MySQL 重建数据，不把 SQLite 文件直接挂载为 MySQL 数据目录。

## 当前限制

- 本地 Docker 守护进程需要先运行；
- 若所在网络对 PyPI 使用了无法被 Docker 基础镜像验证的代理证书，默认构建会安全失败；仅在受控开发网络中可显式使用 `docker compose build --build-arg PIP_ALLOW_INSECURE_INDEX=1` 绕过该证书校验，生产环境不要开启；
- Docker 初始化不导入受限人才/高校工作簿；
- 可靠来源时间覆盖不足，趋势字段仍保持 `insufficient_history`；
- 生产环境必须替换 Compose 中的演示密码和 JWT Secret，并将数据库放入受控存储。
