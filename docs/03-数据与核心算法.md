## 能力抽取

每份 JD 依次执行：

1. 结构化切分职责、硬性要求和加分项。
2. 用 L4 表面词和别名检索原文，归一到标准技术节点。
3. 根据否定、教育描述、公司介绍、业务语境和宽泛词规则做上下文复核。
4. 保存命中原文、位置、技术编码、状态和特征快照。
5. 对 `needs_review` 候选可调用 DeepSeek 做闭集二次判断。

DeepSeek 只能返回 `accepted`、`rejected` 或 `uncertain`，并必须引用输入中逐字存在的证据。模型输出还要经过 JSON Schema、技术编码、证据存在性和置信阈值校验，只有全部通过的高置信 `accepted` 才回写。

本轮全量复核处理 735 条：203 条判断接受，其中 201 条达到回写条件；480 条拒绝、52 条不确定，另有 4 条校验失败。最终技术候选为 7,057 已接受、534 待审核。

## 岗位聚类

岗位聚类是“技术能力结构相似的一组真实 JD”，不是关键词本身，也不是正式职业名称。算法使用归一化技术特征进行多视图分组和 Top-K 归属，并保留灰区、单例和稳定簇编码。

- 最新输入 3,534 条具备聚类资格的 JD。
- 结果 2,102 个簇，743 条处于灰区。
- 只有满足 JD 数、企业覆盖和一致性门槛的候选才可能晋升岗位。
- 本轮产生 3 个岗位候选并完成审批，正式岗位总数为 116。

岗位能力由成员 JD 的已接受技术证据聚合。L2 能力节点通常对应多个 L3/L4 命中；覆盖率、证据数和重要度决定图谱边权与展示顺序。

## 图谱投影与布局

关系图同时支持“岗位簇筛选”和“能力筛选”，两者独立生效：

- 岗位聚类节点：按主要技术域着色的实心圆。
- 标准能力节点：白色空心圆，边线使用对应 T1–T7 颜色。
- 渲染：AntV G6 5 Canvas。
- 布局：按技术域分簇的 D3 Force，在节点数达到阈值后由 Web Worker 计算。
- 交互：语义缩放、拖拽缩放、节点选择、按需展开邻居和表格视图。
- 服务端预算：单次关系图最多 1,000 节点；岗位簇上限 1,000，每簇能力上限 40。

当前“技术域簇”是展示布局，不是重新定义聚类结果；大规模性能和视觉密度仍需持续压测。

## 岗位能力更新

同一批 JD 的多代解析由 `job_parse_run_id` 隔离（职责、场景、技术评估均按运行分区）。
聚类按成员 Jaccard ≥0.55 继承稳定簇编码，并识别 continued / born / split / merged /
ended 五种谱系；沿 `continued` 谱系复用既有岗位，生成下一版岗位版本。

- 能力重要度按覆盖率 0.32、必需比例 0.20、企业多样性 0.14、来源多样性 0.08、
  近期活跃度 0.14、职责语境 0.05 加权。
- 与上一版逐技术比对：新增记 `added`；重要度差 ≥10 分或需求类型变化记 `modified`
  并区分 `strengthened` / `weakened` / `type`；差值 <10 分不记录，避免噪声。
- 在多个足够长的时间窗出现前不提议 `removed`。
- 两版样本量相差一倍以上时输出比较告警，防止把采集波动误判为能力变化。
- 审批通过才把上一版 `valid_to` 封口并同步演化事件状态；驳回不截断上一版。

## 新岗位发现与匹配

- 新岗位发现有自动、技术词定向和名称核验三种模式；机械事实与 LLM 表达分开保存。
- 证据锁定到本次推演所绑定聚类运行对应的解析运行，避免多代解析混算。
- 技术成熟度按事件类型权重 × 相关度 × 时间衰减 × 来源质量累积，`alpha=0.17`
  （实测累积量分布 1.3–17.3，早期 0.85 会在累积量约 5 时压满上限而失去区分度）。
- 里程碑挂在 L1/L2 而 JD 证据在 L3，无直接证据的节点沿父链继承祖先证据，
  每上溯一层按 0.6 折减相关度；有直接证据的节点始终优先。
- 分档为证据门控：`budding` 需 ≥2 个观测窗，`emerging` 需 ≥3 个观测窗、
  ≥1 条应用证据、成熟度 ≥0.35 且任务缺口 ≥0.25。
- 推演发布的岗位 `origin_type_code='inference_derived'`，其标准 JD 恒为
  `is_market_evidence=false`。
- 人岗匹配按能力覆盖、可迁移关系、目标约束和证据完整度等维度确定性计分。
- LLM 不可用时两者均回退为规则文本，不影响候选事实、总分和审核流程。

## 已知数据限制

- 只有 1,691 条 JD 带真实采集时间且集中在两天；其余 2,027 条源数据无日期，
  为跑通多观测窗按 `CRC32(job_code)` 三分到 2026-06/07/08，标记
  `time_quality_code='synthetic_window_spread'`。**当前分档不是市场结论。**
- 趋势统一标记为 `insufficient_history`。
- 任务缺口为六项连乘，衰减快，当前仅 17% 的候选达到 0.25 门槛；
  市场支撑在 JD 8 条 / 企业 5 家即饱和，高证据候选易同分。
- 116 个聚类派生岗位中 32 个只有 1 个技术词，会使技术对的 Jaccard 重合度虚高。
- 现有 120 条 JD 是待双人标注候选，不是金标准。
- 规则和 LLM 复核结果经过审计，但尚未由领域专家给出正式准确率结论。
- 当前 MySQL 快照是开发数据资产，不包含 `.env`、API Key 或用户密钥。
