# 新岗位发现与岗位动态更新：方法论

> 版本 2026-08-19 · 对应实现 `feat/clustering-core-rework` · `ab4ddbf`
> 与 [11-模块设计](11-新岗位发现与岗位动态更新模块设计.md) 的分工：
> 设计报告讲「系统是什么样」，本文讲「为什么这么做、凭什么可信、边界在哪」。

## 0. 本文的陈述口径

方法论文档最容易出的问题是把「方法上应该有效」写成「已经有效」。本文对每一项方法
标注它的证据状态，三档：

| 标记 | 含义 |
| --- | --- |
| **【已实测】** | 有量化结果与可复现命令 |
| **【机制已验证 · 效果未检验】** | 代码跑通、性质有回归测试保证，但「做出来的东西对不对」没有被外部依据检验过 |
| **【未实现】** | 只有设计，不在本文正文描述 |

第二档必须单列，因为它在两个模块里占的比重不小：机制正确不等于结论正确。

## 1. 根本问题：岗位不能由名称定义

具身智能的技术路线尚未收敛，岗位名称随之高度不稳定。同一份工作在语料中可以叫
"具身智能算法工程师""VLA 模型算法工程师""机器人大模型研究员"；反过来，同名的
"算法工程师"在不同公司可能指完全不同的能力集合。

按名称统计得到的是**招聘文案的措辞分布**，不是能力结构的分布。因此两个模块共用一个
方法论前提：

> **岗位由能力集合定义，名称只是能力集合的一个不稳定标签。**

这个前提有三个直接后果，贯穿全文：

1. 岗位的识别必须走「JD → 能力 → 聚类」，而不是「JD → 名称 → 分组」；
2. 岗位的连续性必须用成员集合判定，而不是用名称匹配（§6.1）；
3. "新岗位"必须定义为"既有岗位的能力集合覆盖不了的能力组合"，而不是"没见过的名称"（§7.2）。

## 2. 证据链方法论

这四条是所有模块共同遵守的约束。它们不产生结论，但决定结论可不可信。

### 2.1 可重放

同输入 + 同算法版本 + 同参数 → 必须同结果。做法是每个环节都是一次带版本的**运行
（run）**，记录输入快照哈希、算法版本与全部参数。

**任何影响输出的输入都必须进快照哈希。** 这条看起来是常识，但它的失效是隐蔽的：
开发过程中曾出现把 976 份 JD 的采集时间从 7 月改到 8 月、推演结果却原样返回的情况——
因为快照里没有记录 JD 的采集时间，哈希没变，命中了重放缓存。

**算法行为变更必须升版本号**，否则历史运行的重放缓存会串味。这条同样在开发中被违反过
一次：改了候选排序逻辑但没升版本，第二次运行直接返回了缓存的旧结果。
两次事故都已转成回归测试。

### 2.2 证据逐字可定位

每一条技术要求、每一项能力变更都挂着 `evidence_span`，含字符偏移、原文与内容哈希。
任何结论都可以下钻到具体 JD 的具体句子。

这不只是可追溯性要求，它同时是**一种防伪机制**：无法定位到原文的结论，在流程上就无法
被生成。

### 2.3 机械决策与表达层的边界

**LLM 不得进入任何机械决策路径。** 不由 LLM 决定簇归属、技术编码、评分或分档。
它只有两个合法位置：

1. **表达层改写** —— 把机械事实卡（技术组合、代表职责、证据统计）改写成人类可读的
   岗位名称、一句话定义、形成原因、差异说明。改写结果必须逐条引用机械事实，
   校验不通过则降级为规则模板输出。
2. **离线批处理后物化** —— 结果落成带版本的数据表，机械流程只读冻结结果，
   不在循环内调用 LLM。

这条边界的理由不是不信任 LLM，而是**可重放性**：LLM 输出不稳定，一旦进入决策路径，
同输入同版本就不再同结果，整个证据链的可信度基础就没了。

机械事实本身也可能有误（例如代表职责取自 JD 但语义偏窄），因此事实卡带
`task_text_source` 字段标注来源类型，交给表达层判断是否采用——**把不确定性显式传递下去，
而不是掩盖**。

### 2.4 合成数据显式标记

当前 JD 观测窗有 2,027 份（54%）为初始化时统一赋值的合成日期
（`time_quality_code='synthetic_window_spread'`），真实采集时间只覆盖 2 天；
里程碑有 48 条为估算年份（`data_origin_code='estimated_date'`）。

这些标记不是元数据洁癖。它们直接决定**哪些结论可以写、哪些不能写**：
基于时间轴的演化速率、传导时滞等结论目前一律不可做（§9）。

## 3. 技术坐标系的建立与治理

### 3.1 四层技术词表

| 层 | 含义 | 规模（v1.2） |
| --- | --- | ---: |
| L1 技术域 | T1–T7：算法/传感/整机/数据/系统/安全评测/场景 | 7 |
| L2 技术类 | 如 T1.03 运动规划与控制 | 43 |
| **L3 技术点** | **能力图谱的基本单元**，如 T1.03.02 模型预测控制 | 242 |
| L4 表面词 | 招聘语料中的实际写法，如 `MPC`、`模型预测控制` | 2,073 |

L3 是所有测量的基本单位：能力画像、覆盖率、演化变更项都在 L3 上定义。
L4 只是通往 L3 的入口，本身不参与测量。

### 3.2 版本化治理：为什么用「基线 + 变更集」

**问题**：词表是整条链路的坐标系，它会变；但直接改数据库会切断溯源链
（每个节点都要能回溯到某一行电子表格），且改动无法复现、无法回滚。

**方法**：升版不改数据库，而是

```
基线工作簿 + 治理变更集(JSON) → 渲染新工作簿 → 暂存 → 导入为新版本
```

变更集是仓库内的 JSON，整条链路只依赖仓库文件，不依赖数据库状态，任何人重跑都能得到
**逐字节相同**的工作簿。

**变更集只有三种原语**：下线一个表面词、新增一个技术点、新增一个表面词。
「收窄一个过宽词」不是独立原语——它等于「下线宽词 + 新增若干窄词形」。这样每条改动都能
在工作簿里逐行看到，不需要另一套规则表，也不会出现「规则表与词表不一致」这种状态。

**下线是置「可匹配」为否，不是删行**：谱系与来源留痕全部保留，历史运行仍可解释。

渲染器强制三类校验：新增词与既有词重复、挂载的上级不存在、**同一词形跨节点重复**。
第三条尤其重要——同一个词挂在两个技术点上会让命中归属依赖别名 id 的顺序，
直接破坏可重放性。首次运行即拦下 8 条重复。

**【已实测】** v1.1 → v1.2：L3 229→242，L4 1,872→2,073，下线 12 词、新增 201 词。

### 3.3 表面词的方向性：学术语料还是招聘语料

这是词表治理中最关键的一个判断，也是一个被数据推翻了初始假设的例子。

初版词表的 L4 层有 1,872 个词，实际命中的只有 208 个（11.1%）。初步判断是"L4 层没用"。
**实测推翻了这个判断**：有命中词的长度中位数是 5 字，零命中词是 11 字。

> 问题不是"这一层没用"，而是**收词方向错了**——词表收的是学术长术语，
> 而招聘语料写的是短词、英文缩写、在售称谓。

节点存在但表面词收错的例子：`T2.04.01 惯性测量单元(IMU)` 节点存在，JD 里写的是 `IMU`；
`T4.03.05 仿真平台与工具链` 存在，JD 里写的是 `MuJoCo`、`Isaac Sim`。

因此 v1.2 的新增词全部面向招聘语料：短词、英文缩写、在售称谓。
**【已实测】** 新增词带来的真阳里，`IMU`(6)、`MuJoCo`(3)、`ROS2`(3)、`Jetson`(2)、
`Sim2Real`(2) 等**全部挂在既有 L3 上**——即召回的提升主要来自修表面词，而非补技术点。

### 3.4 歧义消解：语境窗口与权重

少数词天然歧义（"控制系统"既可能指机器人运动控制，也可能指工业 SCADA）。这些词走
歧义规则：语境权重累计 ≥ 1.0 则接受，否则转人工复核。

两处关键设计，都来自对 v1 失效模式的观察：

1. **语境窗口是"命中词所在句"，不是整段。** v1 用整段共现，结果"机器人"这一个泛词
   在语料里放行了大量销售/产品岗——**同段出现不构成句法关联**。
2. **语境词带权重，泛触发词降权。** "机器人"权重 0.5（需与另一个词共现），
   "伺服""运动控制""关节"权重 1.0。权重依据是各词的实测触发频次与复核接受率。

**一个重要的取舍**：v1 有"检测""汽车""大模型"三条规则试图靠语境救回过宽词。
实测这条路走不通——"大模型"的复核接受率仅 1/233。**能靠改词形解决的，就不要靠语境规则救。**
v1.2 把这三个词形下线，规则随之退场，需人工复核的命中从 735 条降到 126 条。

## 4. 测量范围的界定：门控方法论

### 4.1 为什么需要门控

语料来自公开招聘平台，其中大量 JD 与具身智能技术无关（销售、产品、采购、制造工艺）。
它们仍会命中若干技术词，从而污染岗位画像。

门控的方法论立场是：**不删数据，只声明测量范围。** 被判出的 JD 抽取结果与证据完整保留，
只是不纳入聚类与画像聚合，理由逐条记入排除原因。这样做的原因是——测量范围本身是可争议的
判断，把它做成可审计的显式标记，而不是不可见的数据删除。

### 4.2 一个否定结果：证据数量不能识别职能

原计划用"技术证据条数"作为门控判据（条数少 = 不是技术岗）。**实测证明这条路走不通：**

| 门 | Precision | Recall | F1 |
| --- | ---: | ---: | ---: |
| 无门 | 0.585 | 0.444 | 0.505 |
| 证据数门槛 2 | 0.618 | 0.423 | 0.502 |
| **职能标题门** | **0.693** | **0.444** | **0.541** |
| 理想门（标注 role_type 作 oracle） | 0.705 | 0.444 | 0.545 |

原因是：**零证据的非技术岗本来就不产生误报**，过滤它们对证据质量毫无改变；而真正产生
误报的非技术岗（销售/产品/采购）与低证据技术岗在条数上完全重叠，抬高门槛只能等比例
牺牲召回，F1 从门槛 2 起单调下降。

这个否定结果推翻了原任务书的预期，也确立了一条方法论：
**门控的判据必须与要过滤的东西同构。** 要过滤"职能"，判据就得是职能信号，不能用信息量代替。

### 4.3 职能门

改用**岗位名称的职能词**：招聘语料的岗位名高度模式化，职能类别在名称里几乎总是显式出现。
四类规则（商务 / 产品与职能管理 / 制造工艺与质量 / IT 运维与安全），纯机械子串匹配，
确定性、逐条可解释、不引入 LLM。

**【已实测】** 标注集上 P 1.000 / R 0.925，几乎打满理想上限，**且零召回损失**
（TP 与 FN 完全不变）。全语料 3,718 份判出 848 份（净效果 798 份）。

口径说明：判的是「**非具身智能技术岗**」，不是「非技术岗」。电镀/抛光/SMT 有自己的
技术性，但不属于具身智能能力图谱的测量对象。

**已知不足**：按标题过滤会漏掉标题不含职能词的工艺岗——`sop`/`bom`/`dfm` 等制造术语
仍分别命中 145/134/65 份参与聚类的 JD。

### 4.4 语种门：承认工具的能力边界

整条特征管线面向中文语料（中文切字符二元组、英文只留实词）。语料中 96% 是中文，
英文 JD 拿到的是稀疏向量，**只能与彼此匹配**。

**【已实测】** 它们会聚成一个 65 份的簇，其中 62% 是英文 JD（语料里 59 份英文 JD 有 40 份
落在里面），而同等规模的其它簇英文占比为 0。检查其成员：

> helix data creator / ai researcher / battery test engineer / biomechanics researcher /
> chief of staff / commercial launch technician

这不是一个岗位，是**「特征管线表示不了的 JD」的残余桶**，一旦被晋升为岗位就是纯粹的假阳性。

方法论立场：**当工具处理不了某类输入时，正确做法是声明边界并把它排除出测量范围，
而不是让它以退化形式参与测量。** 中文字符占比低于 10% 的 JD 标记
`unsupported_feature_language`。

**代价必须声明**：这部分岗位（59 份，占参与聚类 JD 的 4.2%）在能力图谱中没有覆盖。

## 5. 岗位的操作化定义

### 5.1 多通道相似度

岗位相似度定义在五个通道的加权余弦上：

| 通道 | 权重 | 依据 |
| --- | ---: | --- |
| responsibility 职责 | 0.326 | 职责稳定而名称不稳定，故权重最高 |
| capability 能力 | 0.272 | L3 技术点及其重要度 |
| title 名称 | 0.217 | 去除城市/编号等噪声后的名称词元 |
| domain 技术域 | 0.109 | T1–T7 分布 |
| level 层级 | 0.076 | 序数相似度：同级 1.0、相邻 0.5、跨两级 0.0 |

**职责权重高于名称**是 §1 前提的直接落实。

原设计还有一个 `scenario` 通道占 0.08，但场景特征从未被填充、恒为 0——相似度的
**有效满分只有 0.92**，阈值 0.36 实际卡在 0.391 的位置上。摘掉空通道并归一化后满分回到
1.0，默认阈值同步按 1/0.92 上调以保持行为等价，**使后续改动的效果不会与这次口径修正混淆**。

层级相似度原为二值（相同 1、否则 0），于是"初级 vs 中级"与"初级 vs 高级"同样得 0，
丢掉了序关系；语料中 senior 与 middle 各占约一半，这个区别不小。

### 5.2 特征表示：中文无分词的处理

**这是全流程中影响最大的单点缺陷。**

中文没有空格分词。原实现取 `[一-鿿]{2,12}`，即**任意 12 字切片**。后果是两句几乎同义的
职责：

> 负责具身智能机器人**运动控制算法**的设计与实现
> 负责人形机器人**运动控制算法**开发与调优

切点不同，**token 交集为空**，尽管两句都含"运动控制算法"。

**【已实测】** 31,565 个职责 token 中 **74% 只出现在一份 JD 里**——权重最高的通道
一直在贡献噪声而非信号。

英文侧是另一种失效：两句英文职责的交集是 `{and, for, control, robots}`，一半是虚词；
`and` 是职责通道第 11 高频的 token。这正是英文 JD 互相吸引的原因。

**方法**：中文切**字符二元组** + 英文停用词过滤。二元组会引入噪声词，但 IDF 加权会把
高频二元组压下去——这是无分词器场景的标准做法。修复后上面两句共享 9 个 token。

选择二元组而非引入分词器（jieba 等）的理由：分词器本身带词典与版本，会引入一个新的
不可控依赖，且专业术语的切分质量不可保证；二元组无参数、确定性、对未登录词免疫。

### 5.3 聚类与迭代重分配

两阶段：**单遍贪心 leader 聚类** + **Lloyd 式迭代重分配**。

单遍贪心的成员集合会受 JD 进入顺序影响——先进的成员把质心拉偏后，后来更相似的 JD
反而进不来。迭代重分配的作用是消除这一依赖：重算质心 → 全局重分配 → 直到稳定。

两处与教科书 k-means 的差别，都是被约束逼出来的：

1. **批量应用而非边算边移** —— 先用同一批质心算完所有 JD 的目标簇再统一应用。
   边算边移会让结果依赖处理顺序，那正是要解决的问题。
2. **`max_cluster_size` 是硬约束，会破坏 Lloyd 的单调收敛** —— 目标簇满员时按相似度
   降序接纳，落选的留在原簇。因此必须设最大轮次，并检测"划分回到此前状态"的振荡。

够不上阈值的 JD 留在原处，**不强行分配**——它可能是自成一簇的合理离群点。

**【已实测】一个否定结果**：迭代重分配在本语料上只移动 5 份 JD、1 轮收敛，
簇数/单例比/一致性均无变化。碎片化的主因是特征表示（§5.2）而非质心漂移；
小簇的质心本就几乎不漂移，Lloyd 无事可做。

机制保留（默认开启、可关闭），它保证的是"结果不依赖 JD 进入顺序"这一**性质**，
**不能据此宣称聚类质量提升**。

### 5.4 阈值标定的判据问题

`assign_threshold` 决定簇的粒度，它的标定暴露出一个方法论问题：**用什么判据？**

**不能用簇内一致性。** 一致性只看簇内相似度，阈值越高簇越碎、一致性越高，
极限是每份 JD 自成一簇、一致性 100——退化解。

改用**轮廓系数**（`s = (a−b)/max(a,b)`，`a` 为到自身质心的相似度，`b` 为到最近的其它簇
质心的相似度；单例簇按惯例记 0）。它同时惩罚碎片化与过度合并，确实有内部极值。

**但轮廓系数的最优点经人工核对是过度合并的，不予采纳。** 最优点处最大的簇装着
`helix data creator` / `ai researcher` / `battery test engineer` / `chief of staff`。
轮廓系数奖励"彼此分离的团块"，而一堆互不相似的 JD 因为离所有簇都远，反而能拿到不差的分数。

> **几何判据不知道什么叫"一个岗位"。**

由此确立本模块的一条方法论立场：**聚类质量的最终判据是"簇能否作为岗位定义使用"，
几何指标只用来缩小搜索范围，不用来做最终决定。** 标定曲线与人工判读一并记录在案。

## 6. 岗位连续性与演化的测量

### 6.1 簇谱系：以成员集合定义连续性

这是动态更新的核心难点：**两次聚类产出的是两批全新对象，怎么知道哪个是哪个的延续？**

按 §1 的前提，连续性不能用名称判定（名称不稳定），只能用**成员集合**：
新簇与旧簇的成员 JD 集合 Jaccard ≥ 0.55 判定为延续。五种关系：
`continued` / `born` / `ended` / `split` / `merged`。

只有 `continued` 的簇才产生**岗位新版本**；`born` 产生新岗位，`ended` 让岗位转为非活跃。
"岗位演化"因此有了严格定义：**同一 `job_role_id` 下相邻两个版本之间的能力要求差异。**

### 6.2 与算法变更的区分

一个被实测抓出来的方法论错误：谱系的前身查询原本按算法版本过滤，导致**每次算法升版，
全部簇都找不到前身而被判为新生，所有岗位被当成新岗位重建。**

**【已实测】** v2→v3 升版那次运行 515 个簇全部判为 `born`、0 个 `continued`；
下一次同版本运行则是 515 个 `continued`、成员重叠度 0.998——**簇本身根本没变，
断裂纯粹是过滤条件造成的。**

修正的依据正是 §6.1：延续与否由成员集合判定，这个判据**与算法内部无关**，
因此不应按算法版本过滤。跨算法版本的谱系边在说明文字中标注，供下游区分
"真实演化"与"换算法"。

该缺陷曾造成 89 个本应是延续的岗位被建成新岗位。**它们全部停在待评审状态，
没有一个进入已批准集合**——这也验证了人工评审门作为机械环节最后防线的设计。

### 6.3 演化的两个层次

- **事件层**（`created` / `updated`）：岗位这一版相对上一版发生了什么
- **变更项层**：逐个技术点的新增、消失、重要度升降，每条挂着支撑它的证据跨度

**【机制已验证 · 效果未检验】** 谱系匹配、版本生成、变更项记录全部跑通并有回归测试。
但**当前语料中不存在真实的时间变化**：全部解析运行覆盖的是同一批 3,718 份 JD，
真实采集时间只跨 2 天。因此现有的演化事件全部是**同一批数据在不同算法/词表版本下的差异**，
不是时间上的演化。

> **这个模块至今没有观测过一次真实的岗位能力变化。** 要验证它，唯一的路是采集第二批
> JD（间隔需以月计）。这是数据缺口，不是工程缺口。

## 7. 新岗位的推断

### 7.1 候选粒度：为什么用频繁闭项集

候选是"一组共同出现的技术点"。原设计用 JD 内**任意两个技术的共现**（技术对），
这让核心测量失效——见 §7.2。

改用**频繁闭项集挖掘**：把每份 JD 的 L3 技术集合当作一条事务，逐层 Apriori 求支持度
达标的项集，限制大小在 2–5，再做闭包过滤。

**为什么必须闭包**：频繁项集天然冗余——若 {A,B,C} 在 20 份 JD 中出现，它的全部子集也至少
出现 20 次，直接枚举会产出大量"同一批 JD 的不同切片"。闭项集（没有任何超集与之支持度
相同）只保留每个支持度等价类里最大的那个，去冗余且不丢支持度信息。

**排序不能只看支持度**：支持度沿子集单调不减，纯按 JD 数排序会让候选名额几乎全被最小
组合占满（**【已实测】** 首次真跑 100 个候选里 82 个仍是二元组，粒度提升等于没做）。
改为按「JD 数 × 组合大小」排序——量纲上等价于该组合在语料中支撑的"技术-岗位"证据格点数。

技术数不足以成组合的 JD 用自身完整技术集兜底，**不伪造也不丢失**。

### 7.2 与既有岗位的距离：非对称覆盖率

> **本节结论已随实测修订（2026-08-24）。** 单用非对称覆盖率不成立：它在所有岗位画像上
> 取最大值，加画像只会让它升不会降。已批准岗位版本从 448 增至 676 后，100 个候选的
> 覆盖率全部到 1.0，分类塌成一档。现改为二维判定——覆盖率决定「有没有新能力」，
> Jaccard 决定「是整个岗位还是它的一块」（候选被完全包含时 Jaccard = |候选|/|岗位|，
> 阈值 0.5 即「至少占到一半」）。改后区分度恢复：既有岗位 100 → 73、岗位演化 0 → 27。
>
> **另需声明分母**：既有岗位由同一批 JD 聚类得到，与候选同源，因此「未被覆盖」衡量的是
> 相对**本系统岗位库**的新颖度，不等同于相对劳动力市场。把可比岗位门槛从 2 项提到 8 项
> （可比岗位 532 → 66）后「未被覆盖」始终为 0，说明同源基线下该类别不可能非空。
> 突破路径见《16-上游语料与领先性验证任务书》。


判断"新"需要参照系。用**非对称覆盖率**而非 Jaccard：

```
覆盖率 = |候选技术 ∩ 岗位技术| / |候选技术|
```

问的是"候选的能力有多少已被既有岗位吸收"，与岗位自身还要求多少额外能力无关。
Jaccard 会因岗位技术词更多而错误压低覆盖率——候选 {A,B} 面对要求 {A,B,C,D} 的岗位
实际已被完全覆盖，Jaccard 却只有 0.5。

**候选粒度直接决定这个测量能不能用**：候选是技术对时分母恒为 2，覆盖率只能取
0/0.5/1.0 三个值，三档分类退化成"全覆盖/覆盖一半/不覆盖"。

**【已实测】**

| | 技术对（旧） | 频繁技术组合（现） |
| --- | --- | --- |
| 候选大小 | 恒为 2 | 3–5 |
| 覆盖率取值 | {0, 0.5, 1.0} | {0.333, 0.667, 0.750, 0.800, 1.000} |
| 实测分布 | **91/100 恰好等于 1.0** | 三档均有量 |

**跨词表版本必须按技术编码比较**：节点 id 逐版本独立，按 id 比较会得到恒空的交集，
于是每个候选都被判成"全新岗位"（真跑时 100/100 覆盖率为 0）。技术编码跨版本稳定。

### 7.3 技术成熟度

成熟度由技术里程碑的时间衰减累积决定：

```
成熟度 = 1 − exp(−α · Σ(类型权重 × 相关度 × exp(−0.35·年龄) × 来源可靠度))
```

**类型权重体现证据强度递进**：技术演示 0.45 < 论文 0.55 < 专利 0.60 < 工程突破 0.68
< 融资 0.70 < 标准政策 0.72。排序依据是"该类事件对技术已可用于生产的证明力"：
论文证明可行、专利证明可实现但未必部署、融资反映资本对商业化前景的判断、
标准政策意味着已进入规模化阶段。

**α 是标定出来的，不是拍的**：早期取 0.85 会让累积量超过 5 的技术全部压到 0.98 上限
（15 个有证据节点里 8 个并列），成熟度这一维失去区分度。实测累积量分布在 1.3–17.3，
α=0.17 使该区间映射到约 0.20–0.95，上限不再是绑定约束。

**祖先继承**：里程碑挂在 L1/L2 而 JD 证据在 L3，无直接证据的节点沿父链继承祖先证据，
每上溯一层按 0.6 折减，保证有直接证据的节点始终排在继承者前面。

### 7.4 证据门控分档

**"这是个新岗位"是一个需要多重独立证据才能下的结论**，不是评分高就够。因此分档独立于
评分，纯由证据门控：

| 档位 | 门控条件 |
| --- | --- |
| `potential` 潜在 | 默认档 |
| `budding` 萌芽 | 评分≥45 **且** JD≥3 份 **且** 公司≥2 家 **且** 观测窗≥2 期 **且** 技术已验证 |
| `emerging` 涌现 | 评分≥65 **且** 来源≥2 **且** 应用证据≥1 **且** 技术成熟度≥0.35 **且** 学术产业落差≥0.25 **且** 观测窗≥3 期 |

单一公司、单一来源、缺少时序历史都会被显式标记为风险旗标，随候选一起呈现。

**【机制已验证 · 效果未检验】** 分档机制跑通，当前产出 227 个候选
（potential 6 / budding 218 / emerging 3）。但**这些候选的准确率从未被检验过**——
没有外部依据说明被判为 emerging 的 3 个是否真的在涌现。

## 8. 质量测量方法论

### 8.1 分层标注与指标口径

100 份 JD 按 T1–T7 分层抽样，人工标注"该 JD 应当抽出哪些技术点"，与实际抽取结果做
集合比较，指标为 micro P/R/F1，置信区间用 JD 级 bootstrap 重采样（B=2000，种子固定）。

### 8.2 跨版本对比必须用受限口径

**这是本文最重要的一条测量方法论。**

标注是在旧版词表的代码空间里写的，新版新增的技术点在真值侧**永远缺席**——直接对照会把
新技术点的每一次正确命中都算成误报。

**【已实测】** naive 全口径给出 P 0.451，看起来精确率下降了；而受限口径
（把预测与真值都交到旧版的 229 个代码上，两版在完全相同的判定空间里比较）给出
P 0.585、F1 0.505 vs 0.409——**方向相反**。

> 跨版本比较时，若判定空间本身发生了变化，必须先把空间对齐，否则测的是空间变化
> 而不是质量变化。

### 8.3 标注偏差的显式声明

当前标注为**单人标注、标注者为 AI 助手且非领域专家、未经双人独立标注与仲裁**。
因此所有 P/R/F1 **仅作版本对比的参考基线，不构成性能声明，不得作为金标准**。

为给出全口径参考值所做的新代码补标注，是在看过新版抽取结果之后完成的，
**与被评估系统不独立**，存在确认偏差，其数字系统性偏乐观。这一点在报告中随数字一起声明。

## 9. 方法的适用边界与已知失效模式

方法论文档若不写清失效模式，就只是宣传材料。以下每一条都会使相应结论失效：

| 边界 | 后果 |
| --- | --- |
| **语料无真实时间变化** | 基于时间轴的演化速率、传导时滞、增长趋势等结论**一律不可做**（§2.4、§6.3） |
| **岗位首次出现时间不可观测** | 语料是不完整抽样，"某岗位何时首次出现"无法从数据确定；任何以此为因变量的分析都不成立 |
| **标注非金标准** | 抽取质量的绝对水平不可声明，只可做版本对比（§8.3） |
| **T7 场景域与技术点口径不符** | T7 是场景/行业域，与"技术点"本就不同构，其抽取指标（受限口径 P 0.091）不宜与技术域并列 |
| **英文 JD 无覆盖** | 4.2% 的岗位不在图谱中（§4.4） |
| **几何指标不能做最终判据** | 聚类粒度的选择必须有人工判读参与（§5.4） |
| **推演候选准确率未检验** | "发现了新岗位"目前只是机制输出，不是经验结论（§7.4） |
