## 2.3 技术栈选型

| 层级 | 技术选型 | 选型理由 |
| --- | --- | --- |
| 数据底座层 | Python 3.11 + openpyxl + MySQL 8 + Alembic | 数据以结构化工作簿形式进入，openpyxl 保证每行原始数据可留痕；MySQL 承载全部业务数据与证据；Alembic 管理数据库版本演进，保证结构变更可追溯、可回滚 |
| 算法引擎层 | 自研确定性算法模块（Python）+ DeepSeek（仅表达层） | 岗位归属、技术编码、评分、分档全部由确定性算法完成，保证同输入同版本同结果；大模型严格限制在表达层改写，不进入任何决策路径（详见 4.1.5） |
| 图谱中枢层 | MySQL 关系模型 + AntV G6 | 图谱以关系表建模（节点表 + 关系表 + 证据表），与业务数据同库，保证证据链在一次事务内保持一致；G6 承担前端力导向图与关系图渲染 |
| 应用输出层 | React 19 + FastAPI + Uvicorn + Nginx | 前后端分离；FastAPI 提供异步 API 并由 Pydantic 保证请求与响应的模式约束 |
| 基础设施 | Docker + docker compose + GitHub Actions | 容器化保证环境一致；CI 执行 ruff 静态检查与 pytest 回归测试 |

**关于图存储的选型说明**：本系统未采用原生图数据库，而是在关系模型上实现图谱。理由是本系统的核心约束不是深度路径推理，而是**证据一致性与可重放性**——每个技术要求、每项能力变更都必须与其证据跨度（字符偏移 + 原文 + 内容哈希）保持强一致，且需支持按运行版本回溯历史状态。关系模型的事务保证与外键约束在这两点上更直接；当前图谱的查询模式以邻域展开与层级投影为主，深度未超出关系连接的处理能力。

## 5.1 四级技术词体系

技术词库是全系统唯一的语义标准锚点，所有算法模块的技能识别、比对、推理均以此为参照系。词库采用四级层次结构：

| 层级 | 含义 | 示例 | 当前词条数 |
| --- | --- | --- | ---: |
| **L1 技术域** | 技术大类 | 智能算法与模型、感知与传感、整机与本体 | 7 |
| **L2 技术类** | 技术子方向 | 运动规划与控制、开发与部署工具链 | 43 |
| **L3 技术点** | **能力图谱的基本单元** | 模型预测控制、推理引擎与端侧部署 | 242 |
| **L4 表面词** | 语料中的实际写法 | `MPC`、`模型预测控制`、`TensorRT` | 2,073 |

**层级职责的划分是本词表的一个关键设计**：

- **L3 是所有测量的基本单位**。能力画像、覆盖率、演化变更项全部定义在 L3 上。
- **L4 不参与测量，只是通往 L3 的入口**。同一个 L3 可以有几十个 L4 表面词（不同写法、缩写、英文原名），它们全部归一到同一个 L3。

这一划分解决的问题是：招聘语料中同一技术的写法极度分散（`MPC` / `模型预测控制` / `Model Predictive Control`），若直接以表面词为测量单位，同一能力会被拆成多个互不相干的统计项。

其中 2,039 个 L4 词条参与语料匹配，其余为已下线词条——**下线不是删除**，行与谱系完整保留，只是不再参与匹配，以保证历史运行仍可解释。

### 词表的版本化治理

词表会随技术演进而变化，因此它本身是**带版本的主数据**，升版遵循严格流程：

```
基线工作簿 + 治理变更集(JSON) → 渲染新工作簿 → 暂存 → 导入为新版本
```

变更集是代码仓库内的 JSON 文件，整条链路只依赖仓库文件、不依赖数据库状态，**任何人重跑都能得到逐字节相同的工作簿**。变更集只有三种原语：下线一个表面词、新增一个技术点、新增一个表面词；"收窄一个过宽词"由"下线宽词 + 新增窄词形"组合表达，使每条改动都能在工作簿中逐行审计。

渲染器强制三类校验：新增词与既有词重复、挂载的上级节点不存在、**同一词形跨节点重复**。第三条尤其关键——同一个词挂在两个技术点上会让命中归属依赖内部 ID 顺序，直接破坏可重放性。

**跨版本抽取结果并存**：同一份 JD 可同时持有多个词表版本下的抽取结果，历史解析运行通过各自的词表版本读回原始口径，不被新版覆盖。

**实测效果**：v1.1 → v1.2 的一次治理（下线 12 词、新增 13 个技术点与 201 个表面词），在人工标注集上使抽取 F1 从 0.409 提升至 0.505（受限口径，即把预测与真值都限定在两版共有的代码空间中比较，以排除判定空间变化带来的混淆）。

## 5.2.1 核心实体类型（数量级更正）

| 实体类型 | 标识前缀 | 核心属性 | 当前数量级 |
| --- | --- | --- | ---: |
| 岗位（Job） | `JOB_` | 岗位名称、级别、生命周期状态、版本号、来源类型 | ~510 |
| 技能（Skill） | `SKL_` | 技术点编码、层级、所属技术域 | 242（L3）/ 语料中已出现 241 |
| 岗位候选 | `CAND_` | 技术组合、成熟度档位、覆盖率、分类、风险旗标 | ~230 |
| 技术里程碑 | `MS_` | 事件类型、发生日期、来源可靠度、关联技术点 | 427 |
| 证据跨度 | `EV_` | 文档版本、字符偏移、原文、内容哈希 | 万级 |

> **岗位来源类型是一个必要的区分**：`cluster_derived`（由 JD 聚类归纳得到）与 `inference_derived`（由新岗位推演产出并经审核发布）在图谱中并列但可区分，使"这个岗位是观测到的还是推断出的"始终可查。

## 7.2 创新点二：可重放的证据链与大模型边界

> **说明**：原稿的"三方交叉验证（企业标签 ↔ JD 技能 ↔ 专利布局）"与"幻觉负样本回流优化"尚未实现，本节按实际落地的防控机制重写。

### 行业痛点

大模型在岗位定义、技能描述等生成任务中容易产生幻觉——编造不存在的技能名称、虚构不合理的技能关联、生成与产业实际脱节的岗位描述。现有防控手段多为生成后的人工审核，效率低且覆盖面有限。

更根本的问题在于：**一旦大模型进入决策路径，系统就失去了可重放性**。同样的输入、同样的版本、同样的参数，两次运行得到不同结果——此时任何"结论"都无法被复核，证据链的可信基础即告瓦解。

### 本系统的突破

系统不把幻觉防控当作生成环节的局部问题，而是当作**架构约束**来处理，由三条相互支撑的机制构成：

**机制一：大模型不得进入机械决策路径**

所有岗位归属、技术编码、评分、分档由确定性算法完成。大模型只有两个合法位置：

1. **表达层改写** —— 把机械事实卡改写为可读文本，改写结果必须逐条引用机械事实，校验不通过则降级为规则模板输出；
2. **离线批处理后物化** —— 结果落成带版本的数据表，机械流程只读冻结结果，不在循环内调用。

这条边界使"幻觉"在结构上无法影响任何数值结论——它最多影响文字表述，而文字表述始终与机械事实卡双栏对照（见 6.1.2）。

**机制二：技术词闭集约束**

所有技能项必须来自技术词库，语料匹配采用确定性的多模式串匹配（Aho-Corasick，最长优先消解重叠，要求词边界），**不存在"生成一个技能名"的路径**。词库外的术语无法进入图谱，只能通过治理变更集经审核后正式收录。

对天然歧义的词（如"控制系统"既可指机器人运动控制也可指工业 SCADA），系统采用**同句语境加权判定**：语境词带权重、需在命中词所在句内累计达阈值方予接受，否则转人工复核。这里有一条从实测中得到的取舍原则——**能靠改词形解决的，就不要靠语境规则救**：实测表明泛词的语境放行路径准确率极低（某词的复核接受率仅 1/233），最终选择将该词形下线、由具体词承接，需人工复核的命中量随之从 735 条降至 126 条。

**机制三：证据逐字可定位**

每一条技术要求、每一项能力变更都绑定证据跨度（字符偏移 + 原文 + 内容哈希），任何结论均可下钻至具体 JD 的具体语句。

这不仅是可追溯性要求，更是一种**防伪机制**：无法定位到原文的结论，在流程上就无法被生成。

### 支撑这三条机制的工程约束

| 约束 | 落实方式 |
| --- | --- |
| **可重放** | 同输入 + 同算法版本 + 同参数 → 必须同结果。每个环节都是一次带版本的运行，记录输入快照哈希、算法版本与全部参数 |
| **输入完整进快照** | 任何影响输出的输入都必须进哈希。开发中曾出现修改数据后结果原样返回的情况（快照未覆盖该字段），已转为回归测试 |
| **行为变更必须升版本号** | 否则历史运行的重放缓存会串味。此项亦曾被违反并造成缓存串味，同样已转为回归测试 |
| **合成数据显式标记** | 凡非真实采集的时间戳、估算年份均带标记，并据此限定哪些结论可以成立 |

### 技术创新要素

- 机械决策与语言表达的架构级分离，及"事实卡逐条引用"的表达层校验
- 技术词闭集约束下的确定性语料匹配，与同句语境加权的歧义消解
- 输入快照哈希 + 算法版本号双重隔离的可重放运行模型
- 证据跨度（偏移 + 原文 + 哈希）贯穿全链路的溯源设计

### 已验证与待验证

**已验证**：可重放性、证据可定位性、词表闭集约束均有回归测试保证；歧义规则改造的效果有量化对比（需复核命中量 735 → 126）。

**待验证**：表达层改写的事实一致性目前依靠规则校验与人工审核保证，**尚未建立自动化的一致性评测指标**。本方案不就表达层的幻觉率作出量化声明。
