任务书范围，有些做出来是负结果，有些确实没做。写在这里，比合并时才发现好。

## 一、先说三条硬缺口

这三条是验收时最容易被问住的，单独拎出来。

### 1. 人工审核环节完全没有走过

227 个候选**全部是 `pending`**，0 个 approved，0 个正式岗位来自候选。
这直接导致 RC-01 的四项指标里有三项**无法计算**：

| 任务书要求的指标 | 现状 |
| --- | --- |
| `Precision@K` | ✗ 需要人工判断候选是否成立，没有人工结论 |
| 人工通过率 | ✗ 分母为 0 |
| 风险标记命中率 | ✗ 需要人工判断标记是否正确 |
| 证据完整率 | ✗ 可以算但没算（`evidence_ids` 与应用证据都已落库） |

**必须避免的一个混淆**：我们做了留出重发现实验，报的是 `Recall@K`。
这**不能替代** `Precision@K`——`Recall@K` 用"历史岗位能否被重新发现"当真值，
不需要人工判断；`Precision@K` 问的是"提出来的候选有多少真的成立"，
必须有人工判断。两者测的是不同的东西，方向也相反。

### 2. 三种发现模式只跑过一种

代码里三种模式都在（`service.py:140`：`automatic` / `technology_directed` /
`name_inference`），但实际运行记录里：

| 模式 | 运行次数 |
| --- | ---: |
| `automatic` | 52 |
| `technology_directed` | **0** |
| `name_inference` | **0** |

RC-01 测试任务 2 要求"分别运行三种模式"，实际只覆盖了三分之一。

### 3. 三阶段 vs 五级潜水机制的对照与决定没有做

任务书原文要求负责人"比较两者并形成决定：保留三阶段并修改 PPT，
或设计可验证的五级映射并改进实现"。

全仓库检索"五级 / 潜水 / E→A"，**只有任务书本身命中**。
对照表没做，决定也没下。实现仍是 `potential / budding / emerging` 三档
（实测分布：budding 218 / potential 6 / emerging 3），与 PPT 的五级机制不一致。

## 四、结论为负的部分

这些是做了、但结论是"做不出来"或"主张不成立"的。**它们不是缺口，是结果**，
但必须以负结果的形式陈述，不能反过来当成正面结论用。

| 项 | 结论 | 证据 | 已采取的处理 |
| --- | --- | --- | --- |
| 岗位化门槛 θ 的实测标定 | ⊖ 测不出来 | 成熟度与 JD 提及量秩相关 **−0.268**；84.3% 的 L3 因沿 L2 继承取值重复 | θ = 0.35 在文档与数据中显式标为 `configured_not_measured` |
| 技术成熟 → 岗位需求的传导时滞 | ⊖ 标定失败 | 截尾夹逼退化：12 个已跨门槛方向中 11 个已有需求，未到达组仅 1 个；最优切点判别力与"里程碑条数"对照变量**完全相同**（均 91.7%） | `reference_window` 固定为 `null`，只输出排序不输出窗口 |
| 合取门控"抗特定偏差" | ⊖ 无实证支持 | 两种机制下带单一企业/单一来源旗标且进入 `emerging` 的候选**都是 0 个** | 竞赛稿 7.1 已删去该主张，改为只讲可解释性与收紧作用（3 vs 58） |
| 跨域成熟度可比性 | ⊖ 受整理密度支配 | T1 有 343 条里程碑链接，T5 只有 47 条 | 按既定口径仍做跨域排序，偏差在报告中显式声明 |
| 迭代重分配的效果 | ⊖ 效果甚微 | 仅移动 5 份 JD | 保留实现，不作为亮点陈述 |

另有一项**正面**的稳健性结果，同样属于"测了才知道"：
前瞻排序对 θ 稳健——θ 在 0.25–0.45 间扫动，相邻秩相关 **0.857–0.958**；
但单个方向的绝对跨越时点极差最大 **30 个月**，因此只报名次与阶段，不报日期为预测。

## 六、合并前建议补的三件事

按性价比排序。前两件成本低、堵的是验收时最容易被问的洞。

1. **走一遍完整审批闭环**（对应 RC-01 测试任务 6、交付物第 3 条）
   挑 1 个候选走完"发现 → 定义 → 审批 → 正式入库"，把三层结构填实。
   这一件同时解掉验收标准"明确区分算法候选、人工审批结果和正式岗位"的空心问题。

2. **补跑另外两种发现模式**（对应 RC-01 测试任务 2）
   `technology_directed` 与 `name_inference` 代码都在，各跑一次留下运行记录即可。

3. **做三阶段 vs 五级潜水机制的对照表并下决定**（对应 RC-01 交付物第 2 条）
   任务书要求二选一：保留三阶段并修改 PPT，或设计可验证的五级映射。
   这是个需要你拍板的决策，不是我能单方面定的。

**不建议现在补的**：`Precision@K` 与人工通过率需要 20–30 个候选的人工判断，
工作量大且必须由人来做；在没有人工真值之前，任何自动替代都是在造假指标。
