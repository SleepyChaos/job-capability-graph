# 人岗匹配 P0 闭环实现验收报告

> 日期：2026-08-11
>
> 分支：`codex/redesign-from-scratch`
>
> 阶段：简历证据建档、画像留版、岗位匹配、差距与发展路径

## 1. 阶段结论

本阶段已打通首个不依赖 LLM Provider 的人岗匹配 P0 闭环：

```text
TXT / 粘贴文本
→ 简历事实与 L4 表面词映射
→ L3 标准技术能力证据
→ 2–8 轮自适应追问
→ 用户确认画像版本
→ 最新岗位聚类召回与确定性精排
→ 逐技术差距与双方证据
→ 绑定差距的发展路径
```

前端原有的固定人物、固定岗位、固定 78% 分数和固定 12 周路径已经移除。页面现在读取真实数据库，并保存画像版本、匹配运行、岗位聚类、代表 JD、差距和路径之间的绑定关系。

## 2. 事实与版本边界

- 简历原文、用户补充和系统洞察分别保存；
- 技术能力保留原始表达、L3 技术 ID、证据文本、来源类型和置信度；
- 至少完成 2 轮问答才能确认画像，信息足够时可提前结束，最多 8 轮；
- 修改画像创建新版本，原版本及其历史匹配不被覆盖；
- 画像未出现某项能力只标记为“证据不足”，不会自动写成“候选人不会”；
- P0 不读取或使用性别、年龄、民族、婚育等敏感属性，也不把人格推断放入匹配分数。

## 3. 匹配算法 P0

算法版本为 `evidence_match_p0_v1`。输入冻结画像版本、技术证据集合、求职目标和最新成功岗位聚类运行。相同快照重复请求返回同一匹配运行，并处理并发重复请求。

| 维度 | 权重 | P0 依据 |
| --- | ---: | --- |
| 必需能力覆盖 | 40% | 画像 L3 能力与岗位簇 L3 重要能力的加权覆盖 |
| 可迁移能力 | 10% | 是否存在同一 L2 能力域的相邻 L3 证据 |
| 求职目标语义 | 45% | 岗位名称包含关系、词元和中文双字组重合 |
| 个人证据完整度 | 5% | 已映射标准技术能力数量的有界得分 |

总分由机械规则生成，LLM 不直接给分。每个结果保存维度分、权重、推荐依据、代表 JD 和算法版本。差距目前分为“证据不足”和“可迁移”；后续只有用户明确确认不会或深度评测有证据时，才允许进入“已确认缺失”或“掌握深度不足”。

## 4. 发展路径 P0

路径算法版本为 `gap_path_rules_p0_v1`。每一步都绑定一个 `gap ID`，包含目标技术、差距类型、前置步骤、学习重点、具身智能实践任务、验证标准、预计周数和改善维度。

完成按钮目前只记录前端进度，不直接提高匹配分。用户需要提交代码、实验记录、指标和复盘，形成新的画像证据版本后再重新匹配。

## 5. 数据库与接口

迁移 `20260811_0007` 新增 9 张表：原始简历文档、画像主体、画像版本、技术证据、对话轮次、匹配运行、匹配结果、匹配差距和发展路径。

核心接口：

- `POST/GET /api/v1/talent/profiles`；
- `GET /api/v1/talent/profiles/{version_code}`；
- `POST /api/v1/talent/profiles/{version_code}/answers`；
- `POST /api/v1/talent/profiles/{version_code}/publish`；
- `POST /api/v1/talent/profiles/{version_code}/versions`；
- `POST /api/v1/talent/profiles/{version_code}/matches`；
- `POST /api/v1/talent/matches/{result_code}/learning-path`。

## 7. 浏览器验收

使用真实 API 完成桌面端和 390px 移动端闭环验收：

- 粘贴简历后识别 2 项真实标准能力；
- 两轮问答后出现确认入口并成功入库；
- 画像页展示 SLAM、ROS 原文证据和置信度；
- 匹配页 Top-1 为真实 SLAM 岗位簇，展示真实企业、代表 JD、维度贡献和差距证据；
- 发展路径生成 5 个绑定 gap ID 的步骤；
- 重复匹配请求返回同一运行，不再出现开发模式并发 500；
- 页面无控制台警告或错误，移动端无页面级横向溢出。

工程验收结果：后端完整测试 22 项通过，Ruff 格式与规则检查通过，迁移升级/降级测试通过，Alembic 无遗漏迁移，前端 TypeScript 工程检查与 Vite 生产构建成功（1,605 个模块）。

## 8. 明确未完成项

本阶段不宣称以下能力已经完成：

1. 浏览器端目前只开放 TXT 和粘贴文本；PDF、DOCX、扫描件 OCR 仅预留 `pdf_text / docx_text / ocr_text` 后端准入口；
2. 尚未实现文件病毒扫描、旧 DOC 隔离转换、对象存储、脱敏导出和删除请求；
3. 尚未实现项目时间线、技能使用月数、最近使用时间和深度等级的完整抽取；
4. 尚未建立专家标注的简历—岗位金标准集，因此不能宣称匹配准确率达到 90%；
5. 当前语义分使用机械文本相似度，LLM Provider 扩展继续后置；
6. 路径资源推荐、用户日程约束和完成证据审核将在交付阶段补齐。
