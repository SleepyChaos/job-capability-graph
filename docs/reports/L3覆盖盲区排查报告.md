## 0. 结论速览

1. **缺口是成体系的,不是零星漏词**:部署推理工程侧(TensorRT/ONNX/CUDA/Jetson/量化,合计影响
   150+ JD)、仿真栈(MuJoCo/Isaac/Gazebo,109 JD)、实时通信(EtherCAT/CANopen/DDS,135 JD)、
   RL 算法英文缩写(PPO/SAC,55 JD)、电机控制算法(FOC/PMSM/BLDC,23 JD)整层缺失。
   docs/07 证据 3(JD 245)指出的「工程实践类覆盖不足」被全面证实。
2. **结构性机械原因之一:ROS2(134 JD)**。词表只有 `ros`,而匹配器要求 ASCII 词边界,
   `ros2` 中的 `2` 是词字符,导致 `ros` 无法命中 `ros2`——一个词形直接造成上百份 JD 漏报。
3. **Sim2Real 子树零命中但语料在用**:T4.04「Sim-to-Real迁移」L2 节点存在,run 3 该子树 0 命中,
   而语料中 Sim2Real 相关词形出现在 75 份 JD——节点的表面词与招聘语料完全不重叠(与 L4 空转同构)。
4. **零证据段的主要构成不是漏词,而是语料混入**:2,172 份无 accepted 证据 JD 的中文高频词是
   SOP/BOM/DFM/NPI/QC/CNC/FMEA/良率/制程 等制造质量管理词,另有成批英文模板 JD。
   候选词只能覆盖其中 15%(320 份)——**词表修复后仍需窗口 C 的岗位过滤**,这与 07 任务书判断一致。
5. **两条口径建议**:①学术会议词(CVPR/ICRA/NeurIPS,104 JD)是资质信号不是技术点,建议不收;
   ②PyTorch/TensorFlow 等框架词(149 JD)是否算「技术点」需窗口 B 定口径,本报告仅列信号。

## 方法与可复现性

- 高频词抽取:英文按 ASCII 词元(casefold 合并),中文按 2–4 字 n-gram;
  减去 `md_technology_alias` 已收词(英文精确匹配;n-gram 额外剔除别名的子串/包含别名的碎片);
  排除通用词(显式停用词清单 `backend/tools/audit_data/generic_term_stoplist.txt`,随分支提交);
  候选技术点 = 人工判读归并(编码在 `backend/tools/audit_l3_coverage_gaps.py` 的 `CANDIDATES`),
  **频次与 JD 数全部由脚本从快照计算**。
- 探索模式(打印原始英文词元/中文 n-gram 候选池,供复核判读过程):
  `python backend/tools/audit_l3_coverage_gaps.py --discover`
- 重跑(应得到与本文完全相同的数字):
  ```bash
  python backend/tools/audit_export_extraction_data.py
  python backend/tools/audit_l3_coverage_gaps.py
  ```
