# 上游共现的领先性回测报告（U-3）

> 复现：
> ```
> python -m tools.extract_upstream_technologies --corpus /srv/data/upstream/arxiv \
>   --taxonomy-version v1.4 --out /srv/data/upstream/extracted
> python -m tools.experiment_upstream_lead --extracted /srv/data/upstream/extracted \
>   --level L3 --min-cooccurrence 5
> python -m tools.experiment_upstream_lead --extracted /srv/data/upstream/extracted \
>   --level L3 --threshold-sweep 2,3,5,8
> ```

## 结论摘要

按《16》预注册的判据，结论分两部分：

| 检验的命题 | 结论 |
| --- | --- |
| 上游共现携带 JD 频次之外的信息 | ✅ **支持**，由剂量-反应关系支撑 |
| 上游共现领先招聘需求若干年 | ❌ **不支持**，提升度不随时点前移下降 |

**能据此做的**：把「上游反复共现、JD 尚未共现」的技术对作为**值得关注的能力组合**
提示出来。**不能据此做的**：预测某个岗位何时出现——本回测没有给出任何领先期证据。

## 数据

| 项 | 值 |
| --- | ---: |
| arXiv 论文（cs.RO / cs.AI / cs.LG / cs.CV，2019–2026 逐年定额抽样） | 13,282 篇 |
| 命中 ≥2 个 L3 技术点、可用于共现分析 | 2,049 篇（15%） |
| 上游与 JD 共有的 L3 技术 | 100 个 |
| 可组成的技术对 | 4,950 个 |
| JD 快照中已共现的对 | 1,686 个 → **基准率 34.1%** |

## 为什么时间轴只切上游

采集时间 ≠ 发布时间 ≠ 岗位出现时间，三者层层脱节，**JD 侧的时间不能当真值**。
但回测不需要它：上游语料按论文发表日切片，JD 整体当作「现在」的快照。发表日是
文档自带属性、不是采集产物，这条轴干净。T 往前推得越远，测的领先期越长——
命中率与领先期同时得到，一个 JD 时间戳都不需要。

## 主结果（共现门槛 ≥5）

| 切点 T | T 前文档 | 预测对数 | 命中 | 命中率 | 提升度 | 对照臂命中率 | 对照臂提升度 |
| ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 2020 | 258 | 8 | 7 | 87.5% | **2.569** | 62.5% | 1.835 |
| 2021 | 524 | 20 | 19 | 95.0% | **2.789** | 70.0% | 2.055 |
| 2022 | 773 | 37 | 31 | 83.8% | **2.46** | 70.3% | 2.063 |
| 2023 | 1038 | 59 | 53 | 89.8% | **2.637** | 69.5% | 2.04 |
| 2024 | 1259 | 71 | 62 | 87.3% | **2.564** | 69.0% | 2.026 |
| 2025 | 1515 | 85 | 74 | 87.1% | **2.556** | 70.6% | 2.072 |
| 2026 | 1799 | 102 | 88 | 86.3% | **2.533** | 74.5% | 2.188 |

提升度在 2.46–2.79 之间，稳定高于对照臂的 2.03–2.19，但**七个切点上基本持平**，
没有随 T 前移而下降的趋势。

## 剂量-反应扫描

单点比较不足以支撑结论：在默认门槛（≥2）下本方法相对对照臂只领先 1.05×，
处在噪声量级。剂量-反应能区分信号与噪声——若上游共现真的携带信息，要求更强的
上游证据应当让预测更准。

| 共现门槛 | 本方法最高提升度 | 对照臂最高 | 相对优势 | 各切点提升度 |
| ---: | ---: | ---: | ---: | --- |
| ≥2 | **2.241** | 2.126 | 1.054× | 2.114 2.241 2.186 2.221 2.239 2.194 2.192 |
| ≥3 | **2.437** | 2.245 | 1.086× | 2.418 2.437 2.363 2.389 2.301 2.246 2.312 |
| ≥5 | **2.789** | 2.188 | 1.275× | 2.569 2.789 2.46 2.637 2.564 2.556 2.533 |
| ≥8 | **2.936** | 2.202 | 1.333× | 2.936 2.569 2.71 2.484 2.6 2.624 2.632 |

**本方法随门槛单调上升（2.24 → 2.44 → 2.79 → 2.94），对照臂始终持平（2.13–2.25）。**
上游证据越强预测越准，而「热门技术更容易凑到一起」这个基线没有这个性质。
剂量-反应比单点比较难以用假象解释。

## 两处会翻转结论的实现缺陷（已修）

**一、对照臂按枚举顺序取对而非按频次排序。** 首版用 `combinations` 的迭代顺序
截断，取到的是「最高频那几个技术之间的所有对」而非「频次最高的对」，提升度在
2.46 / 2.18 / 0.55 / 1.41 之间乱跳。改为按两个技术频次的**乘积**排序——这正是
独立性假设下共现的期望强度，是该用的零假设。修正后对照臂稳定在 2.03–2.25。
判据恰恰要靠对照臂来定，这个缺陷会直接翻转结论。

**二、判定逻辑没落实预注册判据。** 判据把「随 T 单调下降」与「不随 T 变化」分成
不同结论，而实现只看最高提升度，一条平坦的曲线会被报成「有领先期」。补上单调性
判定后，结论由「支持」变为「部分支持但不构成领先期证据」。

## 抽取完整度对结论的影响

首轮抽取只有 1,061 篇可用（8%），因为英文别名生成的默认值定错——只补「完全没有
英文别名」的技术点，而强化学习已有 `PPO`/`DQN`/`SAC`/`TD3`、运动规划已有 `MoveIt`、
模仿学习已有 `Diffusion Policy`，全是缩写与产品名，恰恰缺 `reinforcement learning` /
`motion planning` / `imitation learning` 这些正文里最常出现的全称。

补齐后（词表 v1.4，可用文档 2,049 篇）：

| | 不完整抽取 | 完整抽取 |
| --- | ---: | ---: |
| 本方法最高提升度（门槛 ≥2） | 2.236 | 2.241 |
| 对照臂最高 | 1.912 | **2.126** |
| 相对优势 | 1.17× | **1.05×** |

**数据变好之后，默认门槛下的优势反而消失了**——上一轮那点领先是别名覆盖不全把
对照臂弄糙造成的假象。这也是为什么结论必须建立在剂量-反应上，而不是单点比较上。

## L2 粒度下这个检验是退化的

43 个 L2 类目中与 JD 共有 36 个，可组成 630 个对而 JD 里已出现 381 个——
基准率 60.5%，提升度的理论上限只有 `1 / 0.605 = 1.65`，实测 1.654 正好顶满。
没有区分空间，因此全部结论都在 L3 粒度上得出。

## 尚未排除的混淆

1. **同源性未完全排除。** arXiv 与 JD 都反映同一个技术生态，两者的共现结构可能
   同为「哪些技术天然属于同一工程栈」的表现，而不存在谁领先谁。平坦的提升度曲线
   与这个解释一致。要分辨，需要能观测到 JD 侧共现**从无到有**的时点，而那正是
   当前数据给不了的。
2. **语料偏向。** 抽样限于四个 CS 分类，硬件与机电类技术（T3）在 arXiv 上本就
   偏少，其共现结构未必能代表市场。
3. **门槛 ≥8 时样本很小**（T=2020 仅剩个位数的对），该行的数字不宜单独引用。

## 对 U-4 的影响

《16》原定「U-3 通过才启动 U-4（组合成岗位并给出前瞻）」。按本回测结果，
**U-4 的「前瞻」部分不应启动**——没有领先期证据，给出时间预测就是编造。
可以启动的是弱化版本：把「上游反复共现、JD 尚未共现」的技术对作为值得关注的
能力组合提示出来，措辞限定在「值得关注」，不含任何时间断言。
