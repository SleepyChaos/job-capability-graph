## 2. 范围边界（**先读这一节，防止越做越远**）

大方针是**深化岗位发现与动态更新模块直到足以支撑论文**。窗口 B–D 属于「为目标补地基」，
不是目标本身。三条边界必须守住：

1. **不追求整体高召回。** 58% 的零证据 JD 中大部分是 CNC / 采购 / SMT / 销售，
   它们本就不该有技术点。**只追求「具身智能技术岗上的高召回」**，
   不要为提升整体召回把词表扩到通用工程领域——那会把项目变成通用招聘 NLP 项目。
2. **做完 B + C 就停下来重测。** 若 F1 达到 0.6+ 即可支撑论文方法章（并诚实报告局限）；
   不够再继续。**不要一次性追求完美词表。**
3. **聚类只做有论文价值的部分。** 迭代重分配与核心能力门槛对应「岗位能力演化的可靠测量」
   这一方法论贡献，必做；相似度权重修补属工程整理，可延后。

  代价是单例比反弹与灰区激增）
- B-2 过滤器目前只在**聚类入口**生效，评估**是否需要前移到抽取入口**

### 窗口 C：词表治理 🔒独占

> 分支 `feat/taxonomy-v1_2` · 依赖：窗口 A · **必须独占，不可并行**

**为什么独占**：技术词版本是 `parse_run` 的输入。C 期间若有人同时改聚类，
参数标定会用旧词表的数据去卡新词表。**C 应由单 agent 串行完成。**

**任务**（优先级自上而下）

- C-1 下线 6 个过宽词（大模型、商业服务、职业教育、ai教育、开源框架、光学组件），
  影响 228 条 accepted
- C-2 收窄 9 个词（多模态大模型、基础模型、检测、汽车、控制系统、仓储物流、
  数据服务、训练场、act），影响 380 条
- C-3 新增 27 组技术点，按 JD 数优先：ROS2(134)、模型量化(156)、推理引擎 TensorRT/ONNX(77)、
  仿真栈 MuJoCo/Isaac(109)、实时通信 EtherCAT/CANopen(135)、Jetson/Orin(52)、FOC/PMSM(23)
- C-4 **修 `ros2` 词形边界**：匹配器要求 ASCII 词边界，`2` 是词字符导致 `ros` 匹配不上 `ros2`，
  一个词形问题漏报 134 份 JD
- C-5 重建歧义规则：语境词与命中词须同句/邻接；「机器人」这类高频触发词降权
  （它触发大模型 84 次、控制系统 38 次）。**「大模型」类语境已被 LLM 复核证伪
  （同词接受率 0.4%），不应再作为放行依据**
- C-6 重建 L4 表面词层：面向招聘语料收短词（在售型号、英文缩写、常见简称）；
  现有 1,872 个学术词转为文献侧别名，不参与 JD 匹配。
  **注意：L4 不是没用（利用率 10.5%），是收词方向错，别整层删掉**

**验收**：在 `annotator_C` 标注集上跑 `evaluate_extraction_quality.py`，
v1.2 的 F1 显著优于 v1.1 的 0.409；给出逐项改动的贡献拆解。

**标注集缺口补充**：标注过程中记录了一批 `MISSING:` 条目（词表无对应节点的技术），
散落在 `annotator_C` 的 `annotator_notes` 中，包括：电池系统/BMS、目标跟踪、
视觉伺服、运动学正逆解、碰撞检测、MIPI/GMSL、DDS、MLOps、DVC 数据版本管理等。
**C-3 应把这批一并纳入评估。**

### 窗口 D：聚类核心机制 ⚙️可并行开发

> 分支 `feat/clustering-core-rework` · 依赖：无（开发）/ B+C（标定） · **可与 B、C、E 并行开发**

**并行说明**：算法实现不依赖词表，**但参数标定必须等 B+C 完成**。
即：可以并行开发 + 串行标定。

**任务**

- D-1 **迭代重分配**（解决质心漂移）：在现有相似度函数上实现 Lloyd 式迭代
  ——重算质心 → 全局重分配 → 直到稳定。
  终止条件：本轮重分配数 < 总数 1%，或达最大轮次（建议 10）。
  每轮重分配数量写入 `quality_metric_json`，收敛过程可审计。
  **注意**：重分配会改变成员集合，而簇谱系依赖成员 Jaccard ≥0.55 匹配，
  需验证收敛后 `continued` 谱系不会大面积断裂
- D-2 **核心能力定义与加入门槛**（设计已定案，直接实现）：
  - 核心能力 = 技术词的**加权出现率** ≥ θ 的集合，权重 = 该成员与质心的相似度
  - 加入门槛：候选 JD 需覆盖核心能力集合的 ≥ ρ 比例，**且**总相似度过阈值
  - 初值 θ=0.5、ρ=0.5，**跑完看分布再定，不要先拍死**
  - **收敛陷阱**：硬门槛会破坏 Lloyd 的单调收敛。被所有簇拒绝的 JD 落入灰区池，
    不强行分配；必须设最大轮次并检测振荡
  - **设计依据**（已讨论定案，不必重开）：「核心能力从成员算出又用于决定成员」的
    反馈回路在单遍设计中确实存在，但**全局重分配收敛后在数学上消解**——收敛条件即
    「每个成员到自己簇质心的相似度 ≥ 到任何其他簇质心」。加权投票用于阻尼迭代
    **过程中**的中间态污染
- D-3（**可延后**）相似度权重修补：`scenario` 通道恒为 0 却占 8% 权重
  （有效满分仅 0.92，阈值 0.36 被隐性抬高）；`level` 通道二值化，初级 vs 中级得 0 分

**验收**：单例簇比例、簇大小中位数、平均一致性三项均改善；
收敛过程可复现（同输入同参数同结果）；核心能力集合可作为簇的能力画像输出。

### 窗口 E：论文方向 B 分析 🔬完全独立

> 分支 `feat/maturity-structure-analysis` · 依赖：无 · **与所有窗口完全独立**

**为什么现在就能做**：这是唯一**不依赖抽取质量修复**的论文方向——
它的时间轴在**技术侧**（427 条里程碑，跨 1959–2026，日期可考），不在 JD 侧。

**研究问题**：技术成熟度（里程碑时间衰减累积）与岗位能力结构之间是否存在系统性关联？

**任务**

- E-1 技术成熟度分布刻画：按 T1–T7 域、按时间段，量化成熟度覆盖与集中度
- E-2 关联分析：成熟度高的技术点是否在更多岗位版本中出现、重要度权重是否更高
- E-3 **结构错位分析**（已有初步发现，值得深挖）：里程碑高度集中在 T1/T2/T4 算法域，
  而 SLAM、ROS、智能仓储、智能制造等高频岗位技术的成熟度为 0
  → *学术里程碑的关注点与产业岗位的能力需求存在系统性错位*
- E-4 区分「产业关注确实偏算法」与「整理者偏好偏算法」——后者是样本偏差，必须声明

**注意**：E-2 的岗位侧数据受抽取质量影响，结论需标注「基于 v1.1 词表，F1 0.409」；
但 **E-1 与 E-3 是纯技术侧观测，不受影响**，可直接作为论文结论。

**数据局限（必须随结论声明）**：427 条里程碑为二手摘要（`secondary_summary`，可靠度 60），
48 条为估算年份（`data_origin_code='estimated_date'`），47 条无技术链接未导入。

## 5. 必须遵守的约束（违反会破坏既有设计）

1. **LLM 不得进入机械决策路径。** 不得由 LLM 决定簇归属、技术编码、评分或分档。
   合法位置：(a) 离线批处理后 materialize 为带版本数据；(b) 表达层改写。
2. **可重放性。** 同输入 + 同算法版本 + 同参数 → 必须同结果。
   任何影响输出的输入变化都必须进 `input_snapshot_hash`。
3. **算法行为变更必须升 `ALGORITHM_VERSION`**，否则历史运行的重放缓存会串味。
4. **参数不得硬编码**，应进 `DEFAULT_PARAMETERS` 并写入 `run.parameter_json`。
5. **证据必须逐字可定位。**
6. **合成数据必须显式标记。** 当前 JD 观测窗 2/3 为合成日期
   （`time_quality_code='synthetic_window_spread'`）；里程碑 48 条为估算年份。
7. **不要在 `main` 或 `codex/redesign-from-scratch` 上直接提交。**
8. **标注结果不得当作金标准。** `annotator_C` 为单人 AI 标注，仅供版本对比。

## 6. 已知陷阱

| 陷阱 | 说明 |
| --- | --- |
| **镜像未重建** | `migrate`/`bootstrap`/`backend` 是三个独立镜像但共用 `./backend` 上下文。只 build backend 会导致 migrate 报 `Can't locate revision`。需三个一起 build |
| **`docker cp` 不持久** | 容器重建即回退，改动必须重建镜像 |
| **`ruff format` 误伤** | 仓库有 17 个文件未按 ruff format 规范，跑 `ruff format app/` 会产生大量无关 diff。CI 只跑 `ruff check`，**只格式化自己改动的文件** |
| **迁移 DDL 自动提交** | MySQL 上 `ADD COLUMN` 即使迁移后续失败也会留下残留列，需手工回退到干净点再重跑 |
| **SQLite/MySQL 迁移差异** | SQLite 不支持 `UPDATE 表 别名`；约束调整需 `batch_alter_table`；MySQL 删旧唯一索引前需先建新索引（外键依赖） |
| **重新解析不继承 LLM 回写** | 首代 7,057 accepted，重解析后 6,856——少的 201 条是 DeepSeek 回写。换代后需重跑 `tools/reassess_technologies_llm.py` |
| **推演去重** | 候选按 `candidate_key`（模式+技术组合）去重，已处置组合不再提出。测试时「新建 0 个」是正常去重行为 |
| **MySQL 中文显示** | 命令行需加 `--default-character-set=utf8mb4` |
| **只写单测不跑真实数据** | 窗口 A-2 的参数暴露缺失与岗位命名撞名 bug 都是单测覆盖不到、真跑才暴露的。**改动聚类/抽取后必须在真实库上跑一次** |
