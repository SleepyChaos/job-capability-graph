## 二、赛题理解与总体思路（P2-P3）

**P2 赛题痛点**
- 多源异构数据（JD 文本 / 人才简历 / 技术词典）缺乏统一语义底座
- 岗位能力需求变化快，传统静态字典难以追踪
- LLM 提取存在幻觉，无证据可溯源，难以落地可信

**P3 总体思路（一张架构图）**
- 统一 SQLite 单一事实源：岗位 / 技能本体（L1-L4）/ 关联 / 聚类 / 简历 / 审核 / 快照
- 数据管线：导入 → 提取 → 聚类 → 图谱 → 匹配 → 演化 全闭环
- 三大主线：**证据溯源 + 置信度门限 + 人工审核**（创新主打）

## 三、统一数据底座（P4-P5）

**P4 统一 ER 模型**：16 张表的关系图（jobs / skills / job_skills / clusters / resumes / reviews / snapshots…）
**P5 数据主体**：真实数据规模（岗位 6,793 / 技能词 505 / 图谱边 16,925 / 聚类 1,680 / 简历 175）
- 迁移质量校验：去重口径（6,673 去重后保留）、证据回填 6,130 + 新命中 8,928

## 四、能力提取与图谱构建（P6-P7）

**P6 词典正则提取（确定性锚点）**
- L1-L4 技能分类体系（AI/大数据/物联网/智能系统 + 具身智能 T1-T7）
- 证据片段溯源（JD 原文定位）+ 子词回溯机制（"深度强化学习"→补发"强化学习"）
- 准确率：P 95.7% / R 100% / F1 97.8%

**P7 岗位聚类与全景图谱**
- 动态聚类 1,680 簇 + L1/L2 分类映射
- 全景图谱（岗位-技能二部图，技术栈/级别视图切换，T 域七簇锚点布局）
- 新岗位发现：聚类卡片（共享技能 / 代表岗位 / 命名来源）

## 五、人岗匹配与差距分析（P8-P9）

**P8 简历解析**
- 三层架构：PDF 文本层（pypdf）→ 词典提取（证据溯源）→ LLM 结构化提取（映射本体，未映射不入表）
- 评测：P 90.7% / 文本内 R 100% / F1 95.1%

**P9 混合匹配引擎**
- 稀疏向量余弦（0.50）+ L1 域分布（0.20）+ 核心技能 Jaccard（0.20）+ 头衔相似度（0.10）
- 差距清单：已具备 / 技能差距（含严重度分档）/ 额外优势
- 抽样 30 份简历 Top10 命中率 100%；语义模型未启用时透明降级声明

## 六、幻觉防控与人工审核（P10-P11，创新点重点）

**P10 防控机制三层防线**
1. 证据溯源：每条图谱边可回溯 JD 原文片段（覆盖 95.3%）
2. 置信度门限：≥90% 且有证据自动放行；LLM 生成/低置信一律待审
3. 未审核不入正式表：图谱只渲染 approved 边

**P11 审核工作台**：聚类命名（1,586 条待审）→ 人工裁决（批准/拒绝）→ 审核日志留痕（reviews 表）

## 七、动态演化（P12）

- 新岗位定义：聚类 → 五要素定义（名称/职责/必备/加分/场景）→ 审核入表
- 能力动态更新：快照 → 更新 JD 重提取 → 差分（新增/删除/修改标注 + 更新说明，snapshot_diffs 留痕）

## 八、测试验证（P13-P14）

**P13 准确率测试**：三项各 ≥90% 达标（JD 解析 / 简历提取 / 匹配命中率）
**P14 单元测试**：70 用例全过，核心模块覆盖率 80%（≥60% 要求）

## 九、部署与交付（P15）

- Docker Compose 一键部署（前后端 + SQLite 卷），端口约定 3000 / 8002
- 数据卷持久化、生产模式说明
