# 镜像包载入说明

**这是本项目的可运行交付物。** 三个预构建镜像 + 一份编排文件，`docker load` 后一条命令
启动，**不需要源代码、不需要联网拉镜像、不挂载任何宿主目录**。

> 同级的 `交付材料-源代码/` 是裁剪版，仅供代码审阅、不能运行（见根目录《源码裁剪说明.md》）。
> 要看系统实际运行效果，用本目录。

## 前置要求

| 项 | 要求 |
| --- | --- |
| Docker Engine | ≥ 24（含 `docker compose` v2 子命令） |
| 可用磁盘 | ≥ 6 GB（镜像 1.75 GB + 数据卷约 2.5 GB + 解压临时空间） |
| 可用内存 | ≥ 4 GB |
| 端口 | 8080（前端）、8000（后端接口） |

## 两步启动

```bash
docker load -i jcg-images.tar.gz
```

```bash
docker compose up -d
```

就这两条。`docker load` 能直接读 `.tar.gz`，不必先解压。

### 首次启动约需 4 分钟

完整运行库（约 660 MB SQL，90 张表）烘在 `jcg-mysql:delivery` 里，首次启动由 MySQL 的
初始化流程自动导入。实测 **3 分 52 秒**从容器创建到接受连接。这期间 `docker compose ps`
里 mysql 显示 `starting` 属正常，backend 会等它健康后才起。

数据导入后落在 `mysql-data` 卷里，之后重启即时可用。

看进度：

```bash
docker compose logs -f mysql
```

出现 `ready for connections` 即导入完成。

| --- | --- |

## 包内容

| 文件 | 说明 |
| --- | --- |
| `jcg-images.tar.gz` | 三个镜像的 `docker save` 归档，405 MB |
| `jcg-images.tar.gz.sha256` | 校验和 |
| `docker-compose.yml` | 镜像版编排，只有 `image:` 没有 `build:` |

校验：

```bash
sha256sum -c jcg-images.tar.gz.sha256
```

载入后的三个镜像：

| 镜像 | 体积 | 内容 |
| --- | ---: | --- |
| `jcg-mysql:delivery` | 1.25 GB | MySQL 8.0 + 已审计的完整运行数据 |
| `jcg-backend:delivery` | 364 MB | FastAPI + SQLAlchemy 后端 |
| `jcg-frontend:delivery` | 136 MB | Nginx + 前端构建产物（含 gzip 预压） |

## 数据说明

镜像内数据是已审计的运行快照，含 4,655 条岗位事实、106 个标准岗位、178 条新岗位发现
候选，其中**双臂协同VLA大模型研究员**与**边缘世界模型部署工程师**两条已入库并带完整
五维画像，可直接在岗位画像图谱中查看。

## LLM 网关（可选）

候选表达层生成与五维画像生成会调用 LLM。**不配置也能跑**——降级为规则输出，功能不报错，
只是文案质量下降。要启用就在 compose 同级放一个 `.env`：

```
APP_LLM_API_KEY=<你的密钥>
APP_LLM_BASE_URL=https://api.deepseek.com/v1
APP_LLM_MODEL=deepseek-chat
APP_LLM_TIMEOUT_SECONDS=120
```

密钥不进镜像、不进仓库，只从这个文件注入。

## 停止与清理

```bash
docker compose down
```

保留数据卷，下次 `up` 秒起。要连数据一起删：

```bash
docker compose down -v
```

删除镜像：

```bash
docker rmi jcg-mysql:delivery jcg-backend:delivery jcg-frontend:delivery
```

## 与源码构建方式的区别

同级 `../deploy/` 下那份 `docker-compose.yml` 是从源码构建的版本，多三个服务：

| 服务 | 镜像版为什么没有 |
| --- | --- |
| `restore` | 要挂源码树的 `./data/runtime` 快照；数据已烘进 mysql 镜像 |
| `migrate` | Alembic 迁移；镜像内数据已在 head 结构上 |
| `bootstrap` | 要挂 `./data/source` 的核心 XLSX 重跑解析与聚类；同上 |

两者跑起来的系统一致。源码版适合要改代码的场景，镜像版适合直接评审运行。

## 排障

| 现象 | 原因与处理 |
| --- | --- |
| `docker compose up` 卡在 mysql 很久 | 正常，首次导入约 4 分钟。`docker compose logs -f mysql` 看进度 |
| 端口占用 / 绑定失败 | 改 `docker-compose.yml` 的 `ports` 左侧。Windows 上还需查 `netsh int ipv4 show excludedportrange protocol=tcp`，系统保留段（常含 8080）绑不上 |
| 前端能开但数据为空 | 后端没起来。`curl http://localhost:8000/api/v1/health` 与 `docker compose logs backend` |
| 岗位画像图谱加载慢 | 图谱产物 39.5 MB，已在镜像内预压为 4 MB 由 nginx 直发；本地访问通常几秒内完成 |
| `docker load` 报磁盘不足 | 载入需要约 1.75 GB 空间存放解压后的镜像层 |

## 安全提示

镜像内的数据库口令是仓库中的开发默认值（`root_password_change_me` / `app_password_change_me`），
且后端未启用认证。**本包用于赛事评审的本地运行，不要直接暴露到公网。**
