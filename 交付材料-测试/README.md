# 交付材料 · 测试

本目录放**测试代码、测试说明与测试结果**三类材料，分两层：后端单元测试（覆盖率口径）与新岗位发现的功能链路测试（端到端可追溯性）。部署材料在同级的 `交付材料-Docker部署/`。

## 一、单元测试（对应「覆盖率 ≥ 60%」）

| 类别 | 材料 | 位置 |
| --- | --- | --- |
| 测试代码 | 38 个测试文件 | 仓库 `backend/tests/`（不在本目录重复一份，避免与源码脱节） |
| 测试说明 | 测试范围、门禁配置、复现命令、四个挂载的必要性 | [`单元测试报告.md`](单元测试报告.md) |
| 测试结果 | pytest 原始输出（含逐文件覆盖率） | [`单元测试输出.txt`](单元测试输出.txt) |
| 测试结果 | 覆盖率 HTML 报告，浏览器打开 `index.html` | [`coverage/`](coverage/) |

**结论：161 项测试全部通过，语句覆盖率 78.79%**，高于要求的 60%。阈值写死在
`backend/pyproject.toml` 的 `fail_under = 60`，低于该线直接判失败，不依赖人工检查。

## 二、功能链路测试（新岗位发现）

验证研究侧（`upstream_gap`）与产业侧（`milestone_gap`）两条链路从输入数据到落库候选、
再到平台呈现的**端到端可追溯性**：数据卡上每一个数字，能否用库里的原始数据现场复算出来。

| 类别 | 材料 | 位置 |
| --- | --- | --- |
| 测试代码 | 导出脚本，口径与判定工具一致，可复跑 | [`功能测试-新岗位发现链路/export_test_chain.py`](功能测试-新岗位发现链路/export_test_chain.py) |
| 测试代码 | 数据库样例的生成脚本与筛选条件 | `功能测试-新岗位发现链路/db/dump_chain.sh` |
| 测试说明 | 主报告：环境、链路结构、逐项核查、已知偏差 | [`功能测试-新岗位发现链路/测试报告.md`](功能测试-新岗位发现链路/测试报告.md)（另有 .docx） |
| 测试数据 | 两条链路的输入样例（技术词、招聘侧基线、证据源） | `功能测试-新岗位发现链路/input/` |
| 测试结果 | 两条链路的候选完整记录（事实卡、表达层、标准 JD、审核任务、入库岗位） | `功能测试-新岗位发现链路/output/` |
| 测试结果 | 数据库样例：两次推演运行全部 43 条候选及其证据/审核/入库记录 | `功能测试-新岗位发现链路/db/` |
| 测试结果 | 平台呈现截图（数据卡、发现库、审核台、图谱、侧栏、画像） | `功能测试-新岗位发现链路/screenshots/` |

**结论：两条链路的招聘侧基线（研究侧 321/2/0、产业侧 44/108/0）均可用库内原始数据现场复算，与候选卡记录逐项吻合。**
未完全复现的只有研究侧的上游共现次数——抽取产物未随运行归档，报告中标注为部分可核并说明原因。

## 打包注意

`coverage/` 是 `pytest --cov-report=html` 的产物，随代码变化即失效，因此**不入 git**
（coverage.py 会在该目录内自带 `.gitignore`）。从仓库克隆的副本里没有它，打包前确认本地已生成，
或按 [`单元测试报告.md`](单元测试报告.md) 的命令重新生成。归档证据以 `单元测试输出.txt` 为准。
